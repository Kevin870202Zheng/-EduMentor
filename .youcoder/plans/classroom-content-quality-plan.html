沉浸课堂内容质量优化方案

版本: v1.0  |  日期: 2026-07-29  |  状态: 规划中

1. 现状问题与根因分析

1.1 问题一：课堂内容质量差

症状：生成的课堂内容泛泛而谈，缺乏针对具体教材的深度讲解，习题不清晰。
根因影响严重程度
Prompt 缺乏知识点具体内容
outline 阶段只传了 name + description + content；content 阶段连 content 都没传		 LLM 只能靠自身训练数据"猜"教学内容 P0
无教材原文传入
course_materials.raw_text 完全没有参与 prompt 构建		 LLM 无法针对教材版本定向生成 P0
无习题库参考
questions 表的习题未传入 prompt		 LLM 生成的题目与课程脱节，无针对性 P1
courseName 传的是 UUID
kp.getCourseId().toString() 是 UUID 而非课程名		 LLM 不知道是哪门课，无法定位课程语境 P1
无层级聚合
点击 CHAPTER 节点只传该节点自身数据，不聚合子节点		 章级课堂缺少年级下具体知识点内容 P0
content-system.md 内容重复
328 行实际包含两遍完全相同的 prompt		 LLM 收到重复指令，可能降低生成稳定性 P2

1.2 问题二：习题不能有效巩固

症状：习题展示不清晰，学生不能通过提交习题获得知识点巩固反馈。
根因说明严重程度
LLM 生成的 quiz 数据质量差
缺少知识点内容上下文 → 题目泛泛、correctIndex 可能错误、选项无迷惑性		 即使提交链路完整，题目本身也没有巩固价值 P0
生成 quiz 动作缺失
LLM 可能只生成了 speech 类型的 action，没有生成 quiz 类型		 课堂里根本没有可交互的习题 P1
提交后的反馈缺少知识关联
不告诉学生"这道题对应哪个知识点"		 学生不知道薄弱环节在哪里 P2

2. 优化目标

一句话目标：当学生在章层级点击"沉浸课堂"时，系统聚合该章下所有知识点内容 + 教材原文 + 习题参考，生成基于真实教材的、含可交互习题的高质量课堂。

2.1 核心原则

  • 入口集中：沉浸课堂的主入口定在章（CHAPTER）层级
  • 内容扎实：LLM 必须收到该章的全部教学内容才能生成
  • 习题可交互：生成的 quiz 必须完整（4 选项 + 正确索引 + 解析），确保学生能够提交并看到知识点关联反馈
  • 可追溯：学生能看到每道题对应的知识点，提交答题后可更新掌握度

5.2 KnowledgeAggregator 详细设计

public class KnowledgeAggregator {

    // 递归查询子节点
    public AggregatedContent aggregate(UUID chapterId) {
        // 1. 获取当前节点信息
        KnowledgePoint chapter = repo.findById(chapterId);
        
        // 2. 递归查找所有直接子节点（SECTION）
        List sections = repo.findByParentKpId(chapterId);
        
        // 3. 对每个 SECTION，查找其 LEAF 子节点
        List sections = sections.stream().map(section -> {
            List leaves = repo.findByParentKpId(section.getId());
            return new AggregatedSection(section, leaves);
        }).toList();
        
        // 4. 格式化输出
        return new AggregatedContent(chapter, sections);
    }
}

// 聚合内容 DTO
public class AggregatedContent {
    private String chapterName;
    private String chapterDescription;
    private List sections;
    
    // 格式化为 LLM 可读的文本
    public String toPromptText() {
        StringBuilder sb = new StringBuilder();
        sb.append("## 本章知识结构\n");
        sb.append("本章包含 ").append(sections.size()).append(" 节");
        int total = sections.stream().mapToInt(s -> s.getLeaves().size()).sum();
        sb.append("，共 ").append(total).append(" 个知识点。\n\n");
        
        for (AggregatedSection section : sections) {
            sb.append("【").append(section.getName()).append("】\n");
            for (KnowledgePoint kp : section.getLeaves()) {
                sb.append("- ").append(kp.getName()).append("\n");
                if (kp.getContent() != null && !kp.getContent().isEmpty()) {
                    sb.append("  内容：").append(kp.getContent()).append("\n");
                }
            }
            sb.append("\n");
        }
        return sb.toString();
    }
}

8. 风险与注意事项

  • 教材内容长度：教材原文可能很长（数万字），需限制在 8000 字以内，否则 token 消耗过大。建议使用 NLTK 或按章节标题截取
  • 聚合内容长度：一个章可能有 10+ 个知识点，全部 content 聚合后可能超过 LLM 上下文窗口。需要做 truncation 或 RAG 式的关键内容提取
  • 空 content 处理：如果某些知识点的 content 字段为空（seed 数据），需要优雅降级 — 至少传 name + description
  • 教材不存在：如果 course_materials 表为空，则 textbookExcerpt 传空字符串，prompt 说明"无教材原文参考"
  • 习题数量：如果 questions 表没有该章节的习题，referenceQuestions 传空，LLM 自行生成
  • LLM token 成本：聚合后的 prompt 可能长达 5000+ token，需要评估 DeepSeek 的 API 成本

9. 实施建议
