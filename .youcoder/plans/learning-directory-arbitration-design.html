📖 课堂学习模块优化：目录节点导航化 + 仲裁人案例分析（模拟仲裁）

v1.0 · 设计稿 EduMentor 2026-08-16 状态：待评审

一、需求背景与目标

用户在使用课堂学习模块时提出两项优化/新增需求：

需求 1：知识树目录节点「纯导航化」

反馈原文：「课堂学习中，知识点上边有『编、章、节』等目录，目前这些目录下面也像知识点一样有题目，显得很突兀。最好是这些目录型节点，下面只展示具体的知识点或章节目录名字，不需要有练习题等和知识点一样的功能，人看了会迷惑。」

目标：目录节点（编/章/节）与知识点（LEAF）在交互上彻底区分——目录节点是纯导航容器，点击后展示其下子目录/知识点清单；练习题等学习功能仅保留在 LEAF 知识点层级。

需求 2：新增「仲裁人案例分析（模拟仲裁）」功能

反馈原文（摘要）：「开始一节的学习前，学生可作为仲裁人完成一份案例分析，按庭审程序主动提问，AI 被设定为无法律基础的普通老百姓（例如：小宇诉晨光玩具店买卖合同纠纷案——原告是『小宇爸爸』，被告是玩具店张老板，双方都用非专业的直观感受表达诉求，AI 要降智）。完成一节学习后，需再次对该案进行模拟裁决，并生成两次模拟裁决的分析报告。这个功能就加载在课堂学习模块。」

目标：在每个知识点（一课）的学习流程中嵌入「课前案例分析 → 学习 → 课后案例分析 → 双裁决对比报告」的完整闭环，帮助学生通过角色扮演理解法律知识。

二、现状核查（代码实况）

对现有代码逐项核查后的结论：

核查项结论说明
知识点类型体系 就绪 knowledge_points.type 支持 VOLUME/PART/CHAPTER/SECTION/LEAF（V12 迁移），KnowledgePointDto 已含 type 字段，前端可据此区分目录节点与 LEAF
目录节点点击后的行为 问题根因 StudentLearning.jsx 中 knowledgePoints = getKpsByCourse 返回全部节点（含目录）；点击任意节点都会执行 loadQuestions(kpId) → GET /v1/questions?knowledgePointId=，若数据库中有题目直接挂在目录节点上，右侧便出现练习题——目录节点被当成了"课"
题目查询后端逻辑 需防御 QuestionService.listQuestionsByKnowledgePoint = findByKnowledgePointId 精确匹配，本身不做目录/LEAF 区分；建议对非 LEAF 节点直接返回空列表（防御历史误挂数据）
掌握度计算 就绪 masteryLevel = 答对次数 / 答题总数（answer_records 聚合）。无显式"学习完成"标记；页面进度条已用 mastery ≥ 0.5 判定"已学习"，可复用作课后仲裁准入标准
v1 模拟法庭（法官模式） 可复用 已有完整实现：moot_court_sessions/messages 表（V21/V22）、MootCourtService（案例生成/对话/判决/报告）、MootCourtRoom.tsx（聊天室 UI）、courtApi.ts。入口已隐藏，代码保留。其对话引擎、结构化输出、报告模板均可作为 v2 仲裁模式的参考底座
v1 与 v2 的差异 需新建 维度不同（v1=课堂 classroomId，v2=知识点 kpId）；角色不同（v1=法官+专业原被告，v2=仲裁人+普通老百姓）；提示词体系不同（v1 引用法条，v2 需降智）。建议新建独立表 + 独立服务，不污染 v1 数据与代码

三、需求 1：知识树目录节点「纯导航化」

3.1 改造思路

核心原则：目录节点只做导航，LEAF 节点才承载学习。改动集中在前端 StudentLearning.jsx，后端加一道防御性校验。

┌─ 知识结构树（左侧）────────────────────────────┐ │ 1 第一编 法律总论 [目录] │ │ ├─ 1.1 第一章 法的概念 [目录] │ │ │ ├─ 1.1.1 第一节 法的本质 [目录] │ │ │ │ ├─ 法的定义 ← LEAF 可学习│ │ │ │ ├─ 法的特征 ← LEAF 可学习│ │ │ │ └─ ... │ └───────────────────────────────────────────────┘ 点击「第一章 法的概念」→ 右侧展示【目录视图】： ┌─ 目录：第一章 法的概念 ────────────────────────┐ │ 📁 第一节 法的本质 → 点击进入该节目录 │ │ 📁 第二节 法的价值 → 点击进入该节目录 │ │ 📄 法的定义 → 点击直接学习 │ │ 📄 法的特征 → 点击直接学习 │ │ ...（仅列出直属子节点，无练习题、无学习内容） │ └───────────────────────────────────────────────┘

3.2 前端改造明细（StudentLearning.jsx）

改造点说明
选中节点分类 在 handleTreeSelect 中读取选中节点的 type：LEAF → 走现有"第 N 课"渲染；VOLUME/PART/CHAPTER/SECTION → 渲染目录视图，不调用 loadQuestions，不设置"学习内容/练习题/出题考核/智慧课堂"等学习功能
新增 DirectoryView 组件 展示当前目录节点的：① 面包屑路径（返回上级入口）；② 直属子节点清单（图标 + 名称 + 子节点数）；③ 子节点类型区分：目录节点可点击进入其目录视图，LEAF 节点可点击直接进入学习（设置 currentKp 并加载题目）；④ 无子节点时的空状态提示
"上一课 / 下一课"导航 switchKp 改为只在 LEAF 节点间跳转（跳过目录节点），避免"下一课"跳到目录视图
知识树选中高亮 目录节点被选中时同样高亮（视觉反馈），但右侧内容为目录视图而非学习视图
目录视图不渲染的内容 不显示「第 N 课」标题、学习内容卡、练习题 Tabs（练习题/待考核/我出的题）、掌握度圆圈、「去课堂生成」「出题考核」按钮——目录节点上这些功能全部隐藏

3.3 后端防御性改造（QuestionController）

改动：QuestionService.listQuestionsByKnowledgePoint 增加校验——若目标知识点 type != 'LEAF'，直接返回空列表。
目的：即使历史数据存在误挂在目录节点上的题目（教师 AI 出题误挂），学生端也不会再看到；教师端习题管理按知识点查询时同样生效，逻辑一致不冲突。

3.4 验收标准

  • 点击任何目录节点（编/章/节），右侧只展示子节点清单，绝不出现练习题、学习内容、出题考核
  • 点击 LEAF 知识点，行为与现在完全一致（学习内容 + 练习题）
  • 目录视图中的 LEAF 子项可一键进入学习；目录子项可逐级下钻并返回上级
  • "上一课/下一课"只在知识点间跳转

四、需求 2：仲裁人案例分析（模拟仲裁）

4.1 功能总览

在每个知识点（一课）的学习流程中，嵌入「模拟仲裁」闭环：

📋 课前仲裁（PRE） → 📖 完成本课学习（掌握度 ≥ 50%） （解锁） → ⚖️ 课后仲裁（POST，同一案件） → 📊 AI 双裁决对比报告
维度课前仲裁（PRE）课后仲裁（POST）
准入条件学习前，随时可进入掌握度 ≥ 0.5（与进度条"已学习"判定一致），否则提示「请先完成本课学习」
案件按当前知识点内容 AI 生成复用课前同一案件（对比才有意义）
学生角色🧑‍⚖️ 仲裁人（主动提问、主持流程、做出裁决）
AI 角色👨‍🌾 普通老百姓原/被告（AI 降智，口语化表达）
产出课前裁决书课后裁决书
报告两份裁决齐全后 → AI 生成《案例分析报告》（认知变化轨迹 / 知识掌握评估 / 学习建议）

4.2 场景示例（用户提供的案件模板）

案件：小宇诉晨光玩具店买卖合同纠纷案
案情：2024 年 9 月 10 日，初中生小宇在晨光玩具店购买遥控机器人模型（398 元），店员宣称"遥控距离可达 10 米"。小宇回家后发现遥控距离仅 2 米，次日要求退货。店主张老板以"使用环境有墙壁遮挡"为由拒绝。小宇认为构成欺诈，要求按《消费者权益保护法》退一赔三。

原告（小宇爸爸）发言："我是小宇爸爸，这店家怎么能骗小孩钱呢？说的能遥控，结果离两步远就没反应了。赔钱，赶快赔钱。"
被告（张老板）发言（示例）："咱这玩具没问题啊，说明书上都写着呢，是小宇家墙挡着信号了。小孩子哪懂这个，退货哪能这么退？"

↑ 本案即"AI 降智老百姓"的典型样本：双方都不讲法条，凭生活直觉和情绪说话。

4.3 角色与流程设计

环节（stage）流程动作AI 行为
0 陈述记录员播报案情 → 原告（AI）陈述原告以老百姓口吻讲"自己吃了什么亏、想要什么"
1 答辩仲裁人（学生）可提问 → 被告（AI）答辩被告强调"我没问题/是误会/不关我事"
2 举证质证双方就证据/事实交锋（AI 交替发言）双方用生活化语言争辩事实细节（说明书、现场、证人等）
3 辩论围绕争议焦点充分辩论双方各自坚持立场，可情绪化但围绕事实
4 裁决仲裁人（学生）提交裁决书记录员播报"请仲裁员作出裁决"

4.4 AI「降智」提示词体系（核心设计）

设计原则：原被告是无法律基础的普通老百姓，AI 必须"降智"。
设定项提示词要求
角色人设 原告/被告均为普通老百姓（如家长、个体店主、普通消费者），文化程度中等，第一次进"仲裁庭"，不理解专业术语；角色卡中给出生活身份与立场（谁、什么职业/身份、为什么生气/委屈）
语言风格 口语化、自然、有情绪（可带语气词），基于生活经验和眼前事实说话；可用重复、反问、感慨表达感受
法条红线 禁止引用法条原文、禁止使用法律术语（"合同""欺诈""举证责任""赔偿标准"等一律不得直接说出）；若必须表达法律含义，用大白话（如"这是骗人""得给个说法""该赔的就得赔"）
发言长度 每次 60~180 字，短句为主；原告突出"委屈+诉求"，被告突出"无辜+反驳"
互动约束 仲裁人（学生）的指令优先，必须正面回应提问；不得代替对方发言；不得提及"我是 AI"

提示词模板（原告示例）：

你是本案原告「小宇爸爸」，一个普通家长。
你的孩子花 398 元买了个遥控机器人，回家发现根本遥控不远，
去找店家退货，店家还凶巴巴地不认账。
你觉得店家就是在骗小孩钱，越想越气，要讨个说法。

【案件事实】{case.fact}
【争议焦点】{case.disputes}

说话要求：
1. 就像跟街坊邻居倒苦水一样，用最平常的大白话；
2. 想说什么就说什么，可以带情绪、可以反问、可以重复强调；
3. 绝对不要讲法条、不要用"合同""欺诈""诉讼"这类词；
4. 每次说 60~180 字，最后落到你的诉求上（比如"这钱必须退！"）。

4.5 案例生成设计

项方案
生成素材当前知识点的 name / description / content；若 content 为空或过短，自动向上扩展父级（父节点 description/content）与同级兄弟知识点名称，保证素材充足
生成方式LLM askStructured 结构化输出，结构复用 MootCourtCase（caseTitle / fact / disputes / legalPoints / plaintiffName / plaintiffClaim / defendantName / defendantDefense / difficulty）；失败降级为基于知识点名称的通识案件模板
案件要求贴近生活（买卖、租赁、侵权、校园纠纷等），案情完整可信，争议焦点 2~3 个紧扣知识点；双方身份为普通老百姓（如"XX 的爸爸""个体店主""邻居"）
案件复用POST 阶段直接读取 PRE 会话的 case_content，不重新生成

4.6 状态机

CASE_GENERATING → OPENING → HEARING → AWARD_READY → AWARDED → REPORTED │生成案例+开庭 │书记员播报 │对话进行中 │仲裁人待提交裁决 └──────────────────────────────────────────────────────┘ POST 阶段：start 时若 PRE 已生成案件 → 直接复用，跳过 CASE_GENERATING 报告：PRE + POST 均为 AWARDED 后可触发生成 → REPORTED

4.7 数据模型（V24 迁移）

-- ① 仲裁会话（每知识点每学生两个：PRE 课前 / POST 课后）
CREATE TABLE arbitration_sessions (
    id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    course_id    UUID NOT NULL,
    knowledge_point_id UUID NOT NULL,
    student_id   UUID NOT NULL,
    phase        VARCHAR(8)  NOT NULL CHECK (phase IN ('PRE','POST')),
    status       VARCHAR(20) NOT NULL DEFAULT 'CASE_GENERATING'
                 CHECK (status IN ('CASE_GENERATING','OPENING','HEARING',
                                   'AWARD_READY','AWARDED','REPORTED')),
    case_content JSONB,          -- AI 生成的案件（结构与 MootCourtCase 一致）
    award        TEXT,           -- 学生裁决书（JSON：result + reason）
    report       TEXT,           -- AI 分析报告（Markdown）
    stage_index  INTEGER NOT NULL DEFAULT 0,   -- 0陈述/1答辩/2举证/3辩论/4裁决
    created_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (knowledge_point_id, student_id, phase)
);
CREATE INDEX idx_ars_kp ON arbitration_sessions (knowledge_point_id, student_id);

-- ② 仲裁消息（独立表，便于回放/审计）
CREATE TABLE arbitration_messages (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    session_id  UUID NOT NULL,
    role        VARCHAR(16) NOT NULL,   -- CLERK/PLAINTIFF_AI/DEFENDANT_AI/ARBITER_STUDENT
    content     TEXT NOT NULL,
    round_seq   INTEGER NOT NULL DEFAULT 0,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_arm_session ON arbitration_messages (session_id, round_seq);

4.8 后端 API 设计（/api/arbitrations）

接口方法说明
/api/arbitrations/{kpId}/start?phase=POST启动/获取仲裁会话；PRE 首次进入生成案件并开庭，POST 复用 PRE 案件；POST 准入校验：掌握度 ≥ 0.5
/api/arbitrations/{kpId}/session?phase=GET查询会话（含案件 + 消息列表 + 裁决）
/api/arbitrations/{kpId}/message?phase=POST仲裁人（学生）发言 → AI 原/被告按"降智老百姓"人设回应（发言中提及"原告/被告"指定回应方）
/api/arbitrations/{kpId}/next-stage?phase=POST进入下一环节（记录员播报 + 对应方自动发言）
/api/arbitrations/{kpId}/award?phase=POST提交裁决书（SUPPORT/REJECT/PARTIAL + 理由，仲裁语境文案：支持请求/驳回请求/部分支持）
/api/arbitrations/{kpId}/reportGET/POST获取/生成双裁决对比分析报告
/api/arbitrations/{kpId}/statusGET查询该知识点仲裁状态（PRE/POST 是否已裁决、报告是否可生成）——供学习页入口卡片展示

4.9 前端 UI 设计

组件设计
入口卡片（StudentLearning） 在知识点学习区（学习内容/练习题下方）新增「⚖️ 案例分析·模拟仲裁」卡片：展示三态——① 课前仲裁（未做/已裁决）；② 课后仲裁（锁定：未完成学习 / 未做 / 已裁决）；③ 分析报告（可生成 / 已生成，点击查看）。点击"进入仲裁"打开仲裁聊天室
ArbitrationRoom（仲裁聊天室） 复用 MootCourtRoom.tsx 的聊天室布局：案件卡（左）+ 对话流（右）+ 快捷指令；文案全面改为仲裁语境（仲裁庭/仲裁员/记录员/裁决书/支持请求/驳回请求）；角色气泡样式区分（原告=红色系、被告=蓝色系、仲裁人=绿色系、记录员=灰）；输入框提示"以仲裁人身份发言，提及「原告/被告」指定回应方"
承载形式 全屏 Drawer 内嵌课程学习页（不离开学习语境），从入口卡片打开；关闭后回到原知识点位置。备选：独立路由
ArbitrationReport（报告页） 复用 MootCourtReport 结构：案件摘要 + 课前裁决 + 课后裁决 + AI 分析报告（认知变化轨迹 / 知识掌握评估 / 学习建议）
API 封装 新增 frontend/src/api/arbitrationApi.ts（对齐 courtApi 结构）

4.10 报告生成

复用 v1 的报告引擎模式：PRE + POST 两份裁决齐全后，LLM 对比两份裁决书 + 案件知识要点，输出三部分：

  1. 认知变化轨迹：课前→课后裁决结果/理由的变化，判断学生是否"学到了"（例如课前凭直觉支持退货、课后能结合"说明与实物不符"给出更扎实理由）
  2. 知识掌握评估：对照知识点核心概念，评估学生对关键要点的理解程度
  3. 学习建议：针对薄弱点给出下一步学习建议（关联到练习题/知识点）
