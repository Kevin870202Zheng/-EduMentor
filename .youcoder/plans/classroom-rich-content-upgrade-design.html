📽️ 智慧课堂内容形式升级方案

让 AI 生成的课堂从「纯文字讲解」升级为「可视化 PPT + 可交互 HTML 组件」的沉浸式体验
版本 v1.0 2026-08-17 参考项目：OpenMAIC

1. 背景与目标

1.1 现状问题

当前智慧课堂（ClassroomPlayback）生成的课堂内容以「教师讲解词 + 白板文字 + 题目选项」为主，存在以下体验短板：

  • 形式单一：4 种场景类型（slide / quiz / discussion / review）本质上都是「文字流」逐条播放，缺乏视觉层级和图形化表达。
  • 白板简陋：wb_draw_text 只是把文字居中展示（部分支持 Markdown），没有真正的图表、公式排版、示意图。
  • 无动手环节：学生全程「听讲 + 答题」，没有可操作的模拟实验、小游戏、交互组件，缺乏 OpenMAIC 倡导的 "Hands-on exploration" 体验。
  • 无视觉演示：讲解复杂概念（如法律中的流程、经济中的供需曲线）时没有图形化辅助，理解门槛高。

1.2 升级目标

  • PPT 化讲授：slide 场景输出「元素级幻灯片布局」（标题 / 要点卡片 / 图表 / 公式 / 示意图），AI 教师逐页讲解，像真实课堂的投影课件。
  • 交互化学习：新增 interactive 场景，由 LLM 生成自包含 HTML 组件（模拟实验、知识小游戏、可操作示意图），学生动手探索。
  • AI 教师驱动组件：AI 教师通过 postMessage 协议对 HTML 组件进行高亮、设值、标注、揭示等操作，实现「教师演示 → 学生操作 → 教师点评」闭环。
  • 最小侵入改造：复用现有「大纲 → 内容 → 动作」生成流水线、数据库 jsonb 存储和播放状态机，仅扩展场景类型、动作类型、提示词模板与渲染组件。

2. 参考项目 OpenMAIC 借鉴点分析

2.1 借鉴结论

OpenMAIC（Open Multi-Agent Interactive Classroom）的核心启示是「Slides are visual aids, NOT lecture scripts」——幻灯片上只放关键词、图表、公式，长篇讲解放进教师的语音动作。其成熟的提示词工程可直接移植/裁剪到本项目。

OpenMAIC 能力实现位置借鉴价值落地方式
元素级幻灯片（text / shape / line / chart / latex / table） slide-content/system.md（937 行） 高 重写 EduMentor 的 content-system.md，新增 slide 元素布局 JSON Schema + 坐标/字号/对齐硬规则
自包含 HTML 模拟组件（canvas/SVG + 滑块 + postMessage） simulation-content/system.md（317 行） 高 新增 interactive 场景：LLM 生成完整 HTML 文档，前端 iframe sandbox 渲染
知识小游戏（GAMES, NOT QUIZZES） game-content/system.md（396 行） 高 interactive 场景的子类型 game：拖拽配对 / 计时挑战 / 模拟操作
Widget 驱动动作（highlight / setState / annotate / reveal） interactive-actions/system.md 高 新增 4 个 ActionType：widget_highlight / widget_set_state / widget_annotate / widget_reveal
28+ 动作类型（spotlight / laser / wb_draw_chart …） lib/action + action-types.md 中 新增 show_slide（展示整页幻灯片布局）动作，暂不引入 spotlight/laser

2.2 技术前提确认

对 EduMentor 现有代码核查结论：

  • ✅ Scene.contentJson 为 jsonb，可存任意结构化 JSON（含 HTML 字符串字段）。
  • ✅ SceneAction.paramsJson 为 jsonb，动作参数可携带 target、state、html 等新字段。
  • ✅ 现有生成流水线（outline → content → actions）与 ActionDispatcher 分发机制可扩展。
  • ⚠️ 前端 ActionType 联合类型、后端 ActionType 枚举、parseAction 解析器需同步扩展（本方案列出全部改动点）。
  • ⚠️ LLM 生成 HTML 有 token 成本与失败率风险（HTML 较长），需设计降级策略。

4.2 slide 场景：元素级布局 JSON Schema（新增）

slide 场景的 content.slides 字段存储 slides[]，每页含 elements[]。AI 教师通过 show_slide 动作逐页展示。

{
  "type": "slide",
  "title": "从生活案例认识概率",
  "content": {
    "teacherScript": "完整讲解词（整页串讲）",
    "slides": [
      {
        "layoutId": "s1",
        "title": "生活中的概率",
        "elements": [
          { "id": "t1", "kind": "text", "x": 60, "y": 80, "w": 880, "h": 76,
            "content": "抛硬币 100 次，正面朝上约 50 次",
            "fontSize": 28, "color": "#1a1a2e", "align": "center" },
          { "id": "chart1", "kind": "chart", "x": 120, "y": 220, "w": 520, "h": 300,
            "chartType": "bar",
            "data": { "labels": ["正", "反"], "series": [[51, 49]] },
            "themeColors": ["#1677ff", "#52c41a"] },
          { "id": "b1", "kind": "shape", "x": 700, "y": 260, "w": 200, "h": 100,
            "shape": "rect", "fill": "#f0f5ff", "radius": 12,
            "label": "P = 1/2" },
          { "id": "l1", "kind": "line", "x": 660, "y": 310, "w": 40, "h": 1,
            "from": [0, 0], "to": [40, 0], "arrow": true }
        ]
      }
    ],
    "guidingQuestions": ["抛 1000 次会更接近一半吗？"]
  },
  "actions": [
    { "type": "speech", "text": "同学们，先看这一页。", "duration": 3000 },
    { "type": "show_slide", "layoutId": "s1", "speech": "抛硬币的结果就藏在这张图里……" },
    { "type": "pause_for_thought", "duration": 3000 }
  ]
}

元素类型（kind）一览

kind说明关键字段
text文本块content, fontSize, color, align, bold
shape色块/圆角卡片/圆shape(rect/circle/round), fill, radius, label
line连线/箭头（思维导图、流程图）from, to, arrow, dashed
chart图表（bar/line/pie/radar）chartType, data{labels,series,legends}, themeColors
latex公式（KaTeX 渲染）latex, color, align
image图片（可选，v1.1）src, caption

硬性规则（写入 slide-layout-rules.md）

  • 画布尺寸 960 × 540（16:9），元素坐标不得越界，四周留 ≥ 50px 边距。
  • 字号层级：标题 28~32 / 要点 20~24 / 正文 16~18 / 注释 14。
  • 每页元素 3~8 个，禁止整段口语化文字上屏（一句话 ≤ 25 字，要点用短句/词组）。
  • 图表数据必须来自知识点上下文，禁止编造无依据数据。
  • 公式一律用 latex 元素，不得塞进 text 元素。
  • P0 检查清单：坐标不重叠、文本宽度 = 字号×字数×1.0 + 边距、箭头贴合。

4.3 interactive 场景：自包含 HTML 组件生成规范（新增）

interactive 场景的 content.widget 字段存储完整 HTML 文档（LLM 单次生成）。前端以 iframe sandbox="allow-scripts" + srcdoc 隔离渲染，杜绝 XSS 与样式污染。

4.3.1 Widget 子类型（由 LLM 依据知识点自行选择）

子类型适用知识点示例
simulation 模拟实验物理规律、经济曲线、法律流程、数学函数拖动滑块改变「车速/反应时间」观察「刹车距离」变化；点击流程图步骤展开对应法条
game 知识游戏配对、分类、排序、记忆拖拽「违法行为 → 对应法律后果」；限时分类「民事/行政/刑事责任」卡片
explore 可操作示意图结构、组成、层级点击「法院体系」各节点高亮并显示职责说明

4.3.2 HTML 生成硬性要求（写入 interactive-widget-rules.md）

  • 自包含：单文件 HTML，内联 CSS/JS，不依赖任何外部 CDN（离线可用），标准 HTML5 结构。
  • postMessage 监听（必需）：实现 SET_WIDGET_STATE / HIGHLIGHT_ELEMENT / ANNOTATE_ELEMENT / REVEAL_ELEMENT 四类消息，供 AI 教师驱动。
  • 控件命名规范：滑块 id="{var}-slider"，按钮 id="{action}-btn"，显示区 id="{var}-display"，关键元素加 data-target 属性。
  • 动画可见性（CRITICAL）：点击启动后必须有明显视觉变化（对象移动/旋转/变色），禁止"数字在变但画面不动"。
  • 公平开局（game）：初始状态安全，玩家不会被 3 秒内秒杀；有清晰开始/重置按钮，按钮状态机正确（启动→暂停→继续→重新开始）。
  • 移动端适配：控制区与画布不重叠，触摸目标 ≥ 44px。
  • 单一 HTML 文档：禁止重复 <!DOCTYPE>，输出以单个 </html> 结束。
  • 内容真实：数值、法条、案例必须来自知识点上下文，禁止编造。

4.3.3 interactive 场景动作序列（写入 action 编排规则）

5.3 安全设计（HTML 组件渲染）

  • 强制 iframe 隔离：<iframe sandbox="allow-scripts allow-same-origin" srcdoc="…">，不注入主文档 DOM。
  • 通信白名单：postMessage 只接受 SET_WIDGET_STATE / HIGHLIGHT_ELEMENT / ANNOTATE_ELEMENT / REVEAL_ELEMENT 四类，且校验 event.origin。
  • 内容净化：生成 HTML 需通过 DOMPurify 清洗（移除 <script> 中非白名单调用、外部 URL 加载）。v1.0 用 sandbox 隔离即可，净化作为 P1。
  • 资源内联：HTML 内禁止外链 CDN（离线可用 + 防追踪）。
  • 数据回传：组件内「完成/得分」等回传通过 postMessage('WIDGET_COMPLETED', …) 单向上报，后端记录到 SceneQuizRecord（v1.1）。

6. 关键提示词模板正文（v1.0 直接可用的落地文本）

6.1 content-system.md 中新增的 slide 布局分节（节选）

## slide 场景：元素级幻灯片布局

当场景类型为 slide 时，除生成 teacherScript（整页串讲词）外，
必须生成 content.slides[]（每页一个布局，通常 1-2 页），并通过
show_slide 动作逐页展示。

### 画布规范
- 画布 960 × 540（16:9），元素坐标 (x,y,w,h) 均为画布内绝对坐标。
- 边距：四周 ≥ 50px，元素间水平间距 ≥ 20px，垂直间距 ≥ 30px。

### 元素类型与字段
| kind    | 字段                                  | 说明                 |
|---------|---------------------------------------|----------------------|
| text    | content, fontSize, color, align, bold | 短句/词组，≤25字     |
| shape   | shape, fill, radius, label            | rect/circle/round    |
| line    | from, to, arrow, dashed               | 连线/箭头            |
| chart   | chartType, data, themeColors          | bar/line/pie/radar   |
| latex   | latex, color, align                   | KaTeX 公式，独立元素 |

### 布局规则（违反即不合格）
1. 一页 3~8 个元素；禁止整段口语文字上屏，一句话 ≤ 25 字。
2. 字号层级：标题 28~32 / 要点 20~24 / 正文 16~18 / 注释 14。
3. 图表数据必须来源于知识点上下文，禁止编造。
4. 公式必须用 latex 元素，禁止塞进 text。
5. 元素不得互相遮挡；文字宽度 = 字数 × 字号 + 内边距 ×2。
6. 每页必须有明确视觉焦点（最大字号或高亮色块）。
7. 数据类知识（占比、趋势、对比）优先用 chart；过程类用 line+shape 流程图；
   概念关系类用 shape 卡片 + line 连线。

6.2 content-system.md 中新增的 interactive 分节（节选）

## interactive 场景：自包含 HTML 交互组件

当场景类型为 interactive 时，生成 content.widget（含完整 HTML 文档），
并通过 launch_widget 装载、widget_* 动作驱动。

### 组件子类型选择
- simulation：变量调节类（物理/经济/流程规律）→ 滑块 + 实时画布反馈
- game：配对/分类/排序/记忆 → 拖拽或点击交互 + 计分
- explore：结构浏览（体系/层级/组成）→ 点击节点展开详情

### HTML 硬性要求
1. 单文件自包含：内联 CSS/JS，禁止外链 CDN，标准 HTML5。
2. 必须实现 postMessage 监听（SET_WIDGET_STATE / HIGHLIGHT_ELEMENT /
   ANNOTATE_ELEMENT / REVEAL_ELEMENT 四类消息）。
3. 控件命名：滑块 id="{var}-slider"、按钮 id="{action}-btn"、
   显示区 id="{var}-display"，关键元素加 data-target 属性。
4. 动画可见性：启动后必须有明显视觉变化（移动/旋转/变色/粒子）。
5. 公平开局（game）：初始状态安全，前 3 秒不可失败。
6. 按钮状态机：启动 → 暂停 → 继续 → 重新开始，文本与行为一致。
7. 移动端：控制区与画布不重叠，触摸目标 ≥ 44px。
8. 只输出一个完整 HTML 文档，以单个 </html> 结束。

### 动作序列模式
speech(引入) → launch_widget → widget_set_state(演示关键态) →
widget_highlight(指向关键显示) → speech(让学生动手) →
pause_for_thought → widget_annotate(总结规律) → speech(点评)

6.3 outline-system.md 中新增的 interactive 判定规则（节选）

### 何时安排 interactive 场景
在以下情况，应在课堂中安排 1 个（最多 2 个）interactive 场景：
- 知识点存在「可调节变量 + 即时反馈」的实验性（如速度→刹车距离、价格→供需）。
- 知识点为「过程/流程」型，可通过步骤点击逐步探索（如诉讼流程、决策树）。
- 知识点为「配对/分类」型，可通过拖拽或分类游戏强化记忆（如违法类型→责任）。
- 对纯概念陈述型知识点，不安排 interactive，保持 slide 讲解。

interactive 场景标题示例：
- "动手试试：刹车距离与车速的关系"
- "游戏挑战：把违法行为拖进正确的责任类型"
- "点击探索：一起合同纠纷的诉讼全流程"

interactive 场景必须放在「讲解相关概念之后、总结之前」，
让学生先听懂再动手。

7. 降级与容错策略

风险应对
LLM 生成的 HTML 不完整/JS 报错 ① iframe 渲染失败时显示「组件加载失败」占位卡 + 重试按钮；② 组件 HTML 落库前做结构校验（是否存在 <html> 闭合标签、postMessage 监听、无外部 script src）；③ 校验失败则降级为「教师语音引导 + 静态图表」，不中断课堂。
HTML 生成 token 超限/超时 interactive 场景使用更高 maxTokens；LLM 单次生成仍失败时，降级为 slide 布局讲解该知识点。
JSON 解析失败（HTML 含未转义引号） 生成提示词强制「HTML 中禁止使用双引号字符串，一律单引号」+ JSON 转义规则示例；解析失败重试 1 次。
历史课堂数据兼容 所有新字段均为可选（slides/widget/summaryMap 缺省时走旧逻辑），存量课堂不受影响。
postMessage 时序竞态（动作先于 iframe 就绪） iframe onload 后置 ready 标记；widget_* 动作执行前若未就绪则等待/轮询（≤3s）。

8. 实施计划（分 4 步）

步骤 A：提示词与后端（约 2 天）

  • A1. 重写 outline-system.md：场景类型表 + interactive 判定规则。
  • A2. 新增 slide-layout-rules.md 与 interactive-widget-rules.md，重写 content-system.md（§6 模板正文落地）。
  • A3. 后端枚举扩展（ActionType +6、SceneType +1）、SceneContentGenerator 解析扩展、LLM maxTokens 调整。
  • A4. 单元测试：生成结果结构校验（slides/widget 字段完整性、HTML 基础合法性）。

步骤 B：前端渲染（约 2 天）

  • B1. SlideLayoutRenderer：elements[] → PPT 卡片（echarts 图表 + KaTeX 公式 + 形状/连线）。
  • B2. InteractiveWidgetRenderer + WidgetActionBridge：iframe srcdoc + sandbox + postMessage 桥。
  • B3. ActionDispatcher 分发扩展；WhiteboardRenderer diagram 增强；类型定义更新。
  • B4. 浏览器联调：launch → set_state → highlight → annotate → reveal 全链路。

步骤 C：提示词调优与内容质量验证（约 1.5 天）

  • C1. 选取 3 个代表知识点（物理/法律/数学）跑通全生成链路。
  • C2. 对照 P0 检查清单人工评审布局质量，迭代提示词（重点：文字长度、图表数据真实性、动画可见性）。
  • C3. 降级路径演练（HTML 校验失败 → 静态布局）。

步骤 D：回归与发布（约 1 天）

  • D1. 存量课堂回归（旧数据兼容）。
  • D2. 本地 dev 全链路 + Docker 构建 + 部署腾讯云（含 V26 迁移，如需要）。
  • D3. 浏览器生产回归：生成带 interactive 场景的新课堂并体验。

9. 验收标准

#验收项通过标准
1slide 场景 PPT 化生成的课堂含 ≥1 页元素级幻灯片（含图表或公式或流程连线），前端渲染为 16:9 PPT 卡片，AI 教师 show_slide 逐页讲解
2interactive 场景生成的课堂含 ≥1 个可操作 HTML 组件（模拟/游戏/探索），iframe 安全渲染，滑块/按钮可用
3AI 教师驱动组件播放序列中 widget_set_state / highlight / annotate / reveal 至少各出现 1 次且 iframe 内可见生效
4降级可用人为破坏 HTML 后课堂不崩溃，降级为静态布局继续播放
5旧数据兼容存量课堂（无新字段）播放行为与升级前一致
6安全HTML 组件在 sandbox iframe 内运行，主页面无 XSS 注入、无外部网络请求
⚠️ 范围外（后续版本）：多媒体图片/视频生成、组件完成度数据回写（答题记录）、生成过程动画可视化、spotlight/laser 指针动画、PPT 导出。本方案聚焦「内容形式升级」的最小完整闭环。
