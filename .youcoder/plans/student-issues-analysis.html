📋 EduMentor 学生端 5 大问题 — 根因分析与优化方案

🔍 核心发现：7 个独立 Bug，全部源于同一类问题

所有 5 个用户反馈的问题，追溯到底层是 前后端字段名不对齐 和 API 路径不匹配 两类问题。

问题 1️⃣ 课程学习进度不更新

症状

  • 知识点列表的掌握标签永远灰色"未学习"
  • 右上角进度条永远是 0%

根因 — 字段名三重不匹配

位置当前代码（错误）后端实际返回
容器字段 diagRes.data.dimensions diagRes.data.knowledgeMasteries
掌握度值 d.value d.masteryLevel（0~1 小数）
知识点ID d.knowledgePointId d.knowledgePointId ✅ 匹配
修复方案：修改 StudentLearning.jsx 的 loadData() 和 refreshMastery() 中的两处： 
// 修改前
if (diagRes?.data?.dimensions) {
  diagRes.data.dimensions.forEach(d => {
    if (d.knowledgePointId) map[d.knowledgePointId] = d.value;
  });
}

// 修改后
if (diagRes?.data?.knowledgeMasteries) {
  diagRes.data.knowledgeMasteries.forEach(d => {
    if (d.knowledgePointId) map[d.knowledgePointId] = d.masteryLevel;
  });
}

问题 2️⃣ 学习路径没有内容

症状

  • 学习路径页面一片空白

根因 — HTTP 方法 + 路径 双重不匹配

维度前端调用后端定义结果
路径GET /path/planPOST /api/paths/plan❌ 路径不同
方法GETPOST❌ 方法不匹配 → 405
参数Query paramsRequestBody JSON❌ 格式不同
修复方案：
  1. api.jsx 中 pathAPI 改为 POST + /paths/plan + JSON body
  2. 或后端添加一个对外的 GET /paths/plan 查询接口
  3. 学习路径是学生首次访问时自动创建的（后端 planPath() 会 new + save）

问题 3️⃣ 错题复盘没有联动

症状

  • 错题复盘页面没有数据
  • 与课程学习模块没有联动

根因 — API 路径完全错误

前端请求后端实际端点
GET /api/v1/review/records/{studentId} ❌ 不存在
应改为GET /api/reviews/errors?studentId=xxx

答错时 AnswerService 已经创建了 error_records（已验证通过），但前端读不出来。

修复方案：
  1. 修改 api.jsx 中 errorAPI：api.get('/reviews/errors', { params: { studentId } })
  2. ReviewController 返回的 ErrorRecordDto 中检查字段是否包含前端需要的字段

问题 4️⃣ 我的课程没有联动

症状

  • 选课 Modal 中没有可选的课程
  • 已选课程与左侧导航不一致

根因 — publishedOnly 逻辑 Bug

后端 KnowledgeService.listCourses() 使用 if-else if 链：
  if (keyword != null)     → keyword 分支
  else if (subject != null) → subject 分支
  else if (publishedOnly)  → publishedOnly 分支
  else                     → findAll

当 publishedOnly=true 和 keyword 同时传（前端 filter 逻辑），
publishedOnly 分支永远不会执行！
修复方案：将 KnowledgeService.listCourses() 的条件改为组合式 Specification： 
Specification<Course> spec = Specification.where(null);
if (publishedOnly) spec = spec.and((r, q, cb) -> cb.isTrue(r.get("isPublished")));
if (keyword != null) spec = spec.and((r, q, cb) -> cb.like(r.get("name"), "%" + keyword + "%"));
// 然后用 spec 查询 repository.findAll(spec, pageable)

问题 5️⃣ 学情总览全是 Mock 数据

症状

  • 统计卡片显示 MOCK 数值（0.65、12、20、8）
  • "今日学习建议"显示占位文字
  • 没有测评/答题入口

根因 — 4 处硬编码兜底值 + 字段名不匹配

前端字段硬编码兜底后端实际字段
cp.avg_mastery0.65cp.overallMasteryLevel
cp.mastered_kps12cp.masteredKpCount
cp.weak_kps8cp.weakKpCount
cp.total_kps20cp.totalKpCount
修复方案：
  1. 修正 StudentDashboard.jsx 中所有字段名为后端 camelCase 命名
  2. 移除所有硬编码兜底值（改为 0 或 null）
  3. 添加空状态 UI（"暂无学情数据，请先完成一些练习"）
  4. 在 dashboard 中增加"去学习"快捷入口

💡 核心建议：从源码级消除不一致

当前项目存在一个系统性问题：前后端 DTO 字段名没有统一的契约。

建议后续开发采用以下工作流：

  1. API 文档先行 — 后端修改 DTO 时先更新 Swagger 文档
  2. 前端类型定义 — 每个 API 调用对应的响应类型在 api.jsx 中声明
  3. DTO 统一命名规范 — 全部使用 camelCase，避免 snake_case 混用
好消息：后端核心逻辑（BKT、知识追踪、诊断分析、学习路径规划、错题记录）都是正常工作的。修复全部是前后端对接层的字段名/路径问题，没有架构性问题。
