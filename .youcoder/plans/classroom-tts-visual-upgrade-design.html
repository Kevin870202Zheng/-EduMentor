2TTS 语音升级（M1，最快见效）

2.1 调研结论：候选方案对比

方案音质成本部署评价
⭐ edge-tts
（微软 Edge 神经网络语音）		 自然度高（晓晓/云希/云健 等中文音色） 免费（1.2万 Star，2026 仍在维护） Python 微服务 / docker 容器，5 分钟可跑 首选：零成本、音色接近真人、即插即用
火山引擎豆包 TTS 高（支持情感/克隆音色） 收费（有免费额度） 云 API（需 APP ID + Access Token，与方舟 embedding 的 ARK_KEY 不同套） 备选升级：质量上限最高，但需开通+付费
ChatTTS / CosyVoice 高 免费开源 需 GPU 推理，模型大 本地部署成本高，暂不采用
浏览器原生 SpeechSynthesis 僵硬 免费 无 现状 → 降级兜底

2.2 架构：独立 TTS 微服务 + 后端代理

前端 useTTSPlayer → POST /api/tts/synthesize（Spring Boot 新增） → Python edge-tts 服务（FastAPI, :5080） → 返回 mp3 + durationMs → 播放 + 缓存
  • Python 微服务（tts-service/main.py）：FastAPI + edge-tts 库，接口 POST /synthesize {text, voice, rate} → {audioUrl(本地文件), durationMs}；本地文件缓存（hash(text+voice).mp3）
  • Spring Boot：新增 TtsController（POST /api/tts/synthesize）：调用 tts-service（配置 TTS_SERVICE_URL），成功后把音频缓存到本地目录，返回 GET /api/tts/audio/{id}.mp3 可访问 URL；服务不可用时返回 503
  • 前端：ttsService.ts 无需改（接口契约已就绪），自动从浏览器原生升级到 edge-tts；仍保留浏览器原生为最终兜底
  • 音色选择：默认 zh-CN-YunxiNeural（云希·男声·适合讲师）或 zh-CN-XiaoxiaoNeural（晓晓·女声），可通过 voiceId 切换；rate 0.9（稍慢更清晰）
  • 生产部署：docker-compose 增加 tts-service 容器（Python 3.12 slim + edge-tts），backend 通过内部网络访问；腾讯云服务器需确认微软接口可达（edge-tts 一般可直连）
风险提示：edge-tts 依赖微软 Edge 在线接口（非官方），偶发限流/不可用 —— 已通过「后端 503 → 前端降级浏览器原生」兜底，不影响课堂播放。若后续追求极致音质/情感，可平滑切换到火山豆包 TTS（接口形态一致，只换实现）。

3讲稿优先 → 视觉反向对齐（M2）

3.1 现状 vs 目标

❌ 现状：一次生成

LLM 一次输出 slides + actions，slides 自由发挥。结果：页少、与讲稿句子无绑定、视觉"配不上"讲解。

✅ 目标：讲稿优先、视觉反向对齐

先生成完整讲解稿（分句带语义标签），再让 LLM 扮演 PPT 设计师逐句对齐设计视觉：每页引用讲稿具体句子的关键词/数据，show_slide 精准插在对应 speech 前。

3.2 两阶段生成管线（后端改造）

阶段A：生成讲解稿 → script：按句切分 + 语义标签（概念/数据/对比/流程/举例/设问/结论） → 阶段B：视觉对齐生成 → slides（每页=1~3 句，元素引用句中关键词/数据）+ show_slide 插入位置

3.3 阶段 A：讲解稿生成（script-first 提示词）

输出：完整教师讲解稿（口语化、直接对学生说话）
{
  "script": {
    "sentences": [
      { "seq": 1, "text": "我们先看一个真实案例。", "semantic": "引入", "keywords": ["案例"] },
      { "seq": 2, "text": "这家公司建设的保障房，按规定要建防空地下室，却没有建。", "semantic": "事实", "keywords": ["保障房", "防空地下室"] },
      { "seq": 3, "text": "人防办要求缴费，公司却想免缴。", "semantic": "冲突", "keywords": ["人防办", "免缴"] },
      { "seq": 4, "text": "法院怎么判？违法建设不能享受优惠。", "semantic": "结论", "keywords": ["违法建设", "不享受优惠"] }
    ],
    "guidingQuestions": ["违法建设为什么不能享受优惠？"]
  }
}
约束：
- 每句 ≤ 40 字（字幕友好）；一个知识点 1~4 句
- 语义标签驱动阶段B的视觉选型（数据→图表 / 流程→流程图 / 对比→对照卡）

3.4 阶段 B：视觉反向对齐生成（PPT 设计师提示词）

输入：阶段A的 script.sentences（含语义标签+关键词）
输出：为每句设计视觉呈现，聚类成页
{
  "slides": [
    {
      "layoutId": "s1",
      "title": "真实案例：保障房没建防空地下室",   // 由第1~2句提炼
      "coverSentences": [1, 2],
      "elements": [
        { "id": "t1", "kind": "text", "x":60, "y":80, "w":840, "h":76,
          "content": "保障房 · 防空地下室",         // 必须来自 keywords
          "fontSize": 30, "bold": true, "align": "center" },
        { "id": "c1", "kind": "shape", ... }        // 对照卡
      ]
    }
  ],
  "actions": [
    { "type": "speech", "text": "我们先看一个真实案例。", "duration": 3000 },
    { "type": "show_slide", "layoutId": "s1", "speech": "大家看这一页。" },
    { "type": "speech", "text": "这家公司建设的保障房…", "duration": 5000 }
  ]
}
约束：
- 每页元素内容必须引用对应句子的 keywords（不允许编造页外内容）
- show_slide 必须插在对应 speech 之前（视觉先于讲解）
- 页数 = 句子聚类数（一般 2~4 页），每页覆盖 1~3 句

3.5 后端编排改动

  • SceneContentGenerator：slide 场景改为「两轮 LLM 调用」——先 script 生成，再 visuals 生成；quiz/review/interactive 场景保持单轮（review 的 summaryMap 也可走 script-first 对齐）
  • 新增 prompt 文件：prompts/classroom/script-first-system.md + visual-align-system.md
  • 兼容旧逻辑：LLM 返回失败/超时 → 回退单轮生成（现状）

3.6 前端增强：句-页联动高亮（可选加分项）

  • show_slide 动作增加 highlightElementIds（当前讲解句对应的页内元素 ID 列表）
  • 前端：VisualCanvas 把高亮 ID 传给 SlideLayoutRenderer → 对应元素加描边/发光动画（视觉与语音"咬合"的直观体验）

4PPT 设计大师（M3，视觉精美度）

4.1 提示词升级：扮演资深 PPT 设计师

  • 人设：你是一名有 10 年经验的 PPT 设计师，擅长把抽象概念做成信息层级清晰、视觉优雅的课件页
  • 版式模板库（每页必须选型，禁止自由拼贴）：
    模板适用布局特征
    封面页 Cover场景开场大标题居中 + 副标题 + 装饰色带
    概念页 Concept定义/要点左文右图 / 中心词 + 四周解释卡
    数据页 Data占比/趋势图表为主体 + 结论条（下侧高亮结论）
    对比页 Compare左右对照两栏对照卡 + 中间 VS
    流程页 Flow步骤/流程横向/纵向节点 + 箭头连线
    总结页 Summary场景收尾要点列表 + 金句条
  • 配色系统：每场景从 3 套主题色板选 1 套，整套保持一致
    • 🎨 学术蓝：#1677ff/#69b1ff/#e6f4ff（默认）
    • 🌿 莫兰迪绿：#52c41a/#95de64/#f6ffed
    • 🖤 极简黑白金：#1a1a2e/#8c8c8c/#d4b106
  • 精致度规则：栅格对齐（元素坐标对齐 20px 栅格）、统一圆角（卡片 12px）、统一阴影、标题层级 ≤3 级、每页 1 个视觉焦点、适度留白（≥60px 边距）、装饰元素（页脚圆点/章节序号）

4.2 前端渲染器升级（SlideLayoutRenderer v2）

  • 新增 theme prop（场景级主题色板，由 content 传入），图表/卡片/连线统一取色
  • 卡片样式升级：圆角 12px + 柔和阴影（0 4px 16px rgba(0,0,0,.06)）+ 渐变底
  • 标题区：装饰色带 + 章节序号（如 "02 / 06"）
  • 图表：统一 echarts 主题（字体、色板、去网格线），图表下方自动生成「数据结论条」
  • 流程页：节点卡片 + 箭头自动美化
  • 新增 highlightElementIds 支持（句-页联动，M2.6）

4.3 交互组件（widget）精致化

  • interactive-widget-rules.md 增加 UI 规范：统一配色（与场景主题一致）、圆角卡片、按钮 hover 态、留白、字体层级
  • 前端 InteractiveWidgetRenderer：iframe 外层加主题色边框/标题栏美化

验收标准

  1. TTS：新课堂语音自然（晓晓/云希音色），无机械感；TTS 服务宕机时自动降级浏览器原生，不中断课堂
  2. 讲稿对齐：生成的 slides 每页元素内容能在讲解稿中找到原文/关键词出处；show_slide 在对应 speech 之前
  3. PPT 精美度：新课堂页面有明显版式/配色/圆角阴影设计感，非白底色块
  4. 句-页联动（若做）：讲解到某句时，页上对应元素高亮
  5. 旧课堂回归：旧数据播放不受影响
