👥 同学圈：学生朋友圈 + AI 法律风险提示

v1.0 · 设计稿 EduMentor 2026-08-16 状态：待评审

一、需求背景与目标

需求原文（摘要）：新增「同学圈」入口，放在学生端一级入口。功能与微信朋友圈类似；核心差异化：AI 法律风险提示——当学生发的朋友圈涉及法律问题时（如"今天骑车逆行被警察叔叔抓了"），AI 自动定性法律性质（如"行政违法行为"）并给出风险提示（违反《道路交通安全法》第 XX 条，可被处以……），把朋友圈内容当成案例分析题；涉及法律的都给提示和建议，不涉及的不提示。

目标

  • 提供微信朋友圈式的学生社交场：发动态、点赞、评论
  • AI 法律风险检测成为核心差异化能力：将学生真实生活场景转化为普法案例，潜移默化提升法律素养
  • 与现有「模拟仲裁」「智慧课堂」形成"生活 → 案例 → 仲裁"的学法闭环

二、现状核查

核查项结论说明
学生端一级菜单 就绪 MainLayout.jsx 的 studentMenuItems（10 项），新增一项即可；路由在 App.jsx 学生路由组注册
社交/动态模块 无 代码库中无 moment/feed/community 相关实现，需从零建设（数据模型 + API + 前端）
学生身份信息 就绪 users 表（display_name/avatar_url）+ student_profiles.stage（学段）可用于展示作者昵称、头像、学段标签
LLM 结构化输出 就绪 LLMService.askStructured(system, user, Class, schema) 已用于仲裁案例/学习路径等，可直接复用于法律风险检测（可复用 RAG 向量库 提升法条准确度）
迁移与实体模式 就绪 Flyway V1~V24 规范清晰，新表按 V25 追加

三、功能总览

3.1 信息架构

学生端一级入口新增「👥 同学圈」（建议置于「错题复盘」与「我的课程」之间），路由 /student/moments。

3.2 页面布局（微信朋友圈式）

3.3 核心交互

交互行为
发布动态输入文字 → 发布 → 同步触发 AI 法律检测（约 2~5 秒）→ 卡片上展示检测结果（涉及法律则显示「⚖️ AI 法律风险提示」卡片；不涉及则不显示任何提示）
点赞点击心形切换点赞/取消；红心+数量，实时更新
评论点击「💬 评论」展开评论列表，输入框发表评论；显示评论者昵称+学段
删除作者本人可删除自己的动态（「⋯」菜单）
刷新/加载下拉或点击「加载更多」分页拉取（每页 10 条）

四、AI 法律风险检测设计（核心差异化）

4.1 检测时机

方案：发布时同步检测。内容通常为几十字，单次 LLM 调用约 2~5 秒，反馈即时（发完立刻看到提示，体验最佳）。LLM 超时/失败时降级为「不涉及」，不阻塞发布；可在动态详情提供「🔍 重新分析」入口补检。

4.2 检测输出（结构化）

// LegalReviewResult（存 moments.ai_review JSONB；involvesLegal=false 时存 null）
{
  "involvesLegal": true,          // 是否涉及法律问题
  "category": "交通安全",          // 问题类别（交通/消费/网络/校园/人身财产/行政…）
  "legalNature": "行政违法行为",   // 法律性质定性（民事违法/行政违法/刑事违法/一般违规）
  "legalBasis": "《道路交通安全法》第89条：行人、乘车人、非机动车驾驶人违反道路通行规定的，处警告或者5元以上50元以下罚款……",
  "riskTips": "非机动车逆行易引发交通事故，造成人身或财产损害的需依法承担赔偿责任。",
  "suggestions": ["非机动车应靠道路右侧行驶，不得逆行", "发生事故立即报警并配合交警处理", "可参加交通安全教育学习相关法规"],
  "confidence": "high"             // high/medium/low（不确定时标 low，前端弱化展示）
}

4.3 检测提示词设计

System Prompt 核心约束：

  • 识别范围：交通违法（逆行/闯红灯/无证驾驶）、未成年人消费维权、网络发言（侮辱/诽谤/人肉）、校园欺凌、侵犯隐私、盗窃/损坏财物、合同纠纷、赌博/诈骗等常见生活法律场景
  • 只对"描述自身行为/经历"的内容做定性；日常学习、生活、情感分享（如"今天作业好多""周末去公园啦"）一律 involvesLegal=false
  • 定性口径：区分民事违法 / 行政违法 / 刑事违法 / 一般违规；措辞通俗但准确，面向中小学生
  • 法条引用：优先引用准确条款号（如《道路交通安全法》第 89 条）；不确定时写"依据《XX法》相关规定"而非编造条款号
  • 语气：提示性、教育性、非说教；强调"遇到问题可求助老师/家长/12348 法律援助热线"
  • 隐私边界：不输出学生个人信息，仅分析内容本身

4.4 法条准确度增强（可选，建议二期）

可接入现有 RAG 向量库：将《宪法》《民法典》《道路交通安全法》等常用法律条文向量化入库，检测时先检索相关法条片段作为参考上下文，再让 LLM 输出，显著提升法条准确性。一期先依赖模型知识 + 提示词约束，二期接 RAG。

五、数据模型（V25 迁移）

-- ① 同学圈动态
CREATE TABLE IF NOT EXISTS moments (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    author_id   UUID NOT NULL REFERENCES users(id),
    content     TEXT NOT NULL,                    -- 动态正文（限 500 字）
    ai_review   JSONB,                            -- AI 法律检测结果（LegalReviewResult）；不涉及=null
    like_count  INTEGER NOT NULL DEFAULT 0,       -- 冗余点赞数（避免实时 count）
    comment_count INTEGER NOT NULL DEFAULT 0,     -- 冗余评论数
    is_deleted  BOOLEAN NOT NULL DEFAULT FALSE,   -- 软删除
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_moments_created ON moments (created_at DESC) WHERE is_deleted = FALSE;
CREATE INDEX idx_moments_author ON moments (author_id);

-- ② 点赞（每人每动态一次）
CREATE TABLE IF NOT EXISTS moment_likes (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    moment_id   UUID NOT NULL REFERENCES moments(id),
    user_id     UUID NOT NULL REFERENCES users(id),
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (moment_id, user_id)
);
CREATE INDEX idx_ml_moment ON moment_likes (moment_id);

-- ③ 评论
CREATE TABLE IF NOT EXISTS moment_comments (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    moment_id   UUID NOT NULL REFERENCES moments(id),
    user_id     UUID NOT NULL REFERENCES users(id),
    content     TEXT NOT NULL,                    -- 限 200 字
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_mc_moment ON moment_comments (moment_id, created_at);

六、后端 API 设计（/api/moments）

接口方法说明
/api/momentsPOST发布动态（body: {content}）；服务端同步 AI 检测后返回动态（含 aiReview）；检测失败降级 null
/api/moments?page=&size=GET动态流（分页，10/页）；每项含作者（昵称/头像/学段）、是否本人点赞、评论数；不含全部评论（评论按需加载）
/api/moments/{id}DELETE删除动态（仅作者本人；软删除）
/api/moments/{id}/likePOST点赞/取消（toggle），返回最新 likeCount + liked 状态
/api/moments/{id}/commentsGET评论列表（含评论者昵称/学段）
/api/moments/{id}/commentsPOST发表评论（body: {content}）
/api/moments/{id}/reviewPOST「重新分析」：手动补检 AI 法律风险（LLM 上次失败时用）

九、风险与假设

编号类型说明与对策
R1法条准确性LLM 可能引用不准确的条款号。对策：提示词强约束"不确定时不写条款号"；二期接入 RAG 法条库
R2误报/漏报检测是概率性的。对策：confidence 分级（low 弱化展示 + "仅供参考"）；提供"重新分析"补检；后续可让学生反馈"提示不准确"
R3发布阻塞同步检测 LLM 超时会影响发布体验。对策：超时/异常降级为 null 不阻塞；前端发布框提示"AI 分析中"但动态已发布
R4内容安全同学圈可能出现不当内容。对策：软删除 + 作者删除；后续可加举报/教师可见（二期）
R5成本每条动态一次 LLM 调用。对策：单次调用成本低（短文本）；高频用户可加节流（二期）
H1假设「同学圈」可见范围默认为全体学生（微信朋友圈模式，一期不分区）；如需同学段/同课程可见，加过滤即可
