4. 🔬 后端数据流深度分析

4.1 掌握度计算方式

当前 DiagnosisService.analyze() 的掌握度计算逻辑（L118-125）： 
"SELECT kp.id, kp.name, " +
"SUM(CASE WHEN ar.is_correct THEN 1 ELSE 0 END) * 100.0 / NULLIF(COUNT(*), 0) " +
"FROM answer_records ar JOIN knowledge_points kp ... " +
"GROUP BY kp.id, kp.name"
结论：掌握度 = 正确率（纯统计值），不是 BKT 模型。 每次 GET /diagnosis/profile 请求都实时全表聚合，无需预热。所以只要 answer_records 表有新数据，诊断结果就会变化。

6. ✅ 总结

最根本的问题：AnswerService 只做了一件事——保存答题记录。它没有级联触发任何后续操作。
关于掌握度的好消息：DiagnosisService 每次请求都从 answer_records 实时聚合计算。所以只要 answer_records 有新增数据（答题后已保存），GET /diagnosis/profile 的结果就会自动变化。前端的 refreshMastery() 修复已能让知识点状态和进度条更新。
需要后端修复的根本问题：
  1. 错题复盘完全不可用——因为 error_records 从未被创建
  2. 学习路径不会自动推进——因为没有调用路径节点状态更新
  3. 前端页面切换不刷新——因为所有页面的 useEffect 依赖都不是定时器或焦点事件
