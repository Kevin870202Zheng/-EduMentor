1. 方案 A：讨论场景交互优化（P0）

1.1 现状根因

播放器对 discussion 动作的处置存在「有意等待、无意封死」的结构性矛盾：

  • 等待机制：usePlayback.ts:283-284 — if (type === 'quiz' || type === 'discussion') return;，播放链在此悬挂（不启动 TTS、不调度下一动作），等待学生交互；
  • 但交互窗口不存在：DiscussionRenderer.tsx（96 行）是纯只读卡片（小E头像 + 问题文本 + "思考一下"脉冲提示），无输入框、无观点按钮、无提交、无继续；
  • 继续入口也不通：ActionDispatcher.tsx:78-79 渲染 DiscussionRenderer 时未传 onAdvance（QuizRenderer 传了），且 usePlayback 的 enterLiveMode（讨论模式）虽已导出但无任何组件调用；
  • 结果：讨论动作 = 永久悬挂，唯一出路是底部「下一动作」按钮（且用户不知道要等多久）。

1.2 交互设计目标

  1. 有窗口：讨论场景呈现完整交互面板（观点表达区 + 提交 + AI 回应）；
  2. 有出口：任何时候可「继续学习」（手动按钮），且超时自动继续（防无人值守卡死）；
  3. 轻量：不引入后端 LLM 讨论 Agent（大投入），第一阶段用「预设观点 + 本地回应」闭环；
  4. 不破坏现有双轨模型：讨论仍走覆盖层（isOverlay），视觉轨保持当前页常驻。

1.3 讨论面板交互流程

① 小E 提问卡→ ② 观点快捷选择（chips）→ ③ 自由输入（可选）→ ④ 提交 → 小E 回应→ ⑤ 继续学习（手动/倒计时）
区域内容交互
提问卡（保留现有）小E 头像 + action.prompt/topic 文本进入即有弹跳/渐显动画
观点快捷选择3~4 个预设观点 chips（来自生成侧 options 字段，无则用通用观点模板）点击选中（可多选）；选中后可直接提交
自由输入TextArea（maxLength 200）+ 「发表观点」按钮输入即自动取消 chips 选择状态
小E 回应提交后 0.8s 延迟出现小E 回应气泡（预置回应库轮换，如「这个角度很独特！还有同学补充吗？」）回应出现后启用「继续学习」按钮
倒计时顶部细进度条，时长 = action.duration（默认 60s）到 0 自动触发继续（等效点击「继续学习」）
继续学习主按钮（primary）调用 onAdvance → 播放链恢复
⚠️ 关键决策：倒计时到 0 必须自动继续——即使学生未输入任何观点（无人值守/挂机场景），讨论不得卡死播放链。这与「手动继续」并列作为双出口。

2. 方案 B：视觉提示词重构（P1，参考 OpenMAIC）

2.1 差距分析：当前 vs OpenMAIC

OpenMAIC（清华开源多智能体课堂）的核心 PPT 模板 slide-content/system.md 达 937 行，是「工程化视觉约束」的标杆；EduMentor 当前的 slide-layout-rules.md（82 行）+ visual-align-system.md（81 行）仅覆盖了其中约 40% 的约束能力。

2.3 slide-layout-rules.md 升级内容（核心）

① 文本高度查表（新增，借鉴 OpenMAIC）

LLM 必须按字号 × 行数查表给出元素的 h，杜绝文字溢出/被裁剪：

字号1 行2 行3 行4 行5 行
36px（大标题）54100146192238
32px（页标题）4888128168208
24px（要点）3870102134166
20px（正文）326088116144
16px（注释）26507498122
14px（脚注）24466890112
⚠️ 行高按 1.4 倍计算并向上取整到 2px 栅格；元素 h 不得小于查表值（文字被裁剪 = P0 错误）。

② 对齐与对称规则（新增）

  • 同组元素左边缘/中心线必须对齐，偏差 ≤ 2px（人眼可察觉 5px 差异）；
  • 对称布局（左右两栏/上下镜像）必须使用完全相同的坐标与尺寸数值，禁止"大致对称"；
  • 水平居中：x = (960 - w) / 2；垂直居中同理；
  • 元素间距：垂直 20~50px、多列之间 40~60px、图与说明文字 25~35px。

③ 反例对照教学（新增）

❌ Wrong：标题元素 {x:60,y:40,w:840,h:60}，字号 32、内容 3 行 → 文字溢出被裁剪（查表 3 行应 h ≥ 128）
✅ Correct：{x:60,y:36,w:840,h:128}，字号 32、内容 ≤ 2 行（查表 2 行 h=88，留余量）
❌ Wrong：左右对比卡 x 分别为 70 与 500（视觉错位），卡内文字左右边距不一致
✅ Correct：两卡 x=60 与 500（同宽 400、间距 40），卡内 padding 统一 20px
❌ Wrong：chart 数据 6 项全堆一页，label 超长被截断，无结论条
✅ Correct：chart 只放 3~5 项关键数据 + 下侧结论条（variant: conclusion）点出结论

④ 输出前 P0/P1 自检清单（新增）

🔴 P0（违反即失败，必须全部通过）

  • 每个 text 元素 h ≥ 文本高度查表值（无裁剪）；
  • 所有元素在画布内：x ≥ 0 且 x+w ≤ 960、y ≥ 0 且 y+h ≤ 540；
  • 元素两两不重叠（卡片内层叠除外）；
  • chart 数据必须来自知识点（禁止编造数字）；
  • 元素 content 必须能在对应讲稿句的 keywords 中找到出处；
  • 每页 ≤ 6 个元素、1 个视觉焦点。

🟡 P1（强烈建议，违反需说明理由）

  • 同组元素对齐（左对齐/居中）偏差 ≤ 2px；
  • 间距符合标准（垂直 20~50 / 多列 40~60）；
  • 卡片圆角 12px、阴影柔和、整套页面主题一致；
  • 页边距 ≥ 60px；每页至少 1 个非 text 元素（shape/line/chart）支撑版式。

2.4 visual-align-system.md 增强

  1. 版式模板库 6 → 10：新增 timeline（时间线：大事记/步骤演进）、cycle（循环：流程闭环）、hierarchy（层级：分类/从属）、definition（定义卡：术语/概念）——每个模板给出布局特征与元素构成建议；
  2. 视觉密度控制：每页元素 ≤ 6（保持）、文字总字数 ≤ 60 字、留白 ≥ 30% 页面面积；
  3. 焦点引导强化：highlightElementIds 语义明确为「1~3 个与即将讲解句子强相关的元素」，高亮元素应是页面视觉焦点（大字号/主色/居中位），禁止高亮装饰性元素；
  4. 示例升级：输出格式示例改为「高质量版本」——含卡片 variant、结论条、图表、时间线的完整 JSON，让 LLM 有具体的质量锚点；
  5. 数据真实性硬约束：chart 数据必须来自讲稿 keywords/知识点数据，禁止模型"合理想象"数字；无真实数据时用 concept/flow 模板而非 chart。

2.5 生成校验兜底（后端，可选增强）

在 SceneContentGenerator 解析产物时增加结构校验，失败自动重试 1 次（换更高温度或裁剪约束重发）：

  • 元素越界检查：x+w ≤ 960、y+h ≤ 540；
  • 文本溢出检查：按查表规则估算 h 是否足够；
  • chart 结构检查：data.labels/series 非空且长度一致；
  • highlightElementIds 引用检查：必须指向本页真实存在的元素 id。

2.6 阶段二（可选，暂不排期）

  • image 元素启用：SlideLayoutRenderer 增加 kind: image 渲染（背景图/插图，src 为后端静态资源 URL）；生成侧放开 image 元素（当前 v1.1 预留、明确禁止）；
  • 视觉素材生成服务：复用 tts-service 的容器模式，新增「示意图生成」（文生图 API 或图标库兜底），按知识点自动配图。
