📽️ 智慧课堂播放器改造：视觉常驻 + 语音字幕（视觉优先）

问题：PPT/交互组件"一闪而过"，讲解词独占界面 —— 目标：视觉是主引导、音频如字幕配合视觉

前端播放器架构改造 提示词模板对齐 v1.0

1问题根因（已核实代码）

核心根因：播放器是「单动作单视图、线性互斥」模型 —— 界面每一时刻只渲染"当前这一个动作"：speech 显示大段文字卡片，show_slide 显示 PPT，两者互斥切换、不共存。
现状机制代码位置后果
show_slide 默认停留 4000ms 后自动前进 usePlayback.ts getActionDelay() L78 PPT 一闪而过
speech 渲染为「大段文字卡片」独占内容区 SpeechRenderer.tsx（maxWidth 800 卡片 + 多段文本） 显示的是"演讲文档"
动作执行是线性队列，无"视觉层"概念 usePlayback.ts executeAction() L154-179 视觉与语音永远无法同时呈现
ActionDispatcher 按 type 渲染单一组件 ActionDispatcher.tsx switch L84-170 无"常驻画布"承载视觉状态
提示词固化线性序列 speech→show_slide→speech→show_slide prompts/classroom/content-system.md L32-37 LLM 默认产出"讲一段、闪一页"的节奏
用户期望的目标模型：「视觉层（PPT/组件/白板/知识地图）常驻作为主引导，音频讲解像字幕一样配合视觉，讲解一段对应 1~N 个知识点；视觉切换是低频事件，语音是高频事件。」

2目标架构：双轨播放模型

把播放器从「动作线性互斥」改为「视觉轨（常驻）+ 语音轨（字幕）」双轨并行模型：

🎬 视觉轨（常驻） ← show_slide 切页 / launch_widget 装载组件 / wb_draw 白板 → 保持到下次视觉动作
🎙️ 语音轨（字幕） ← speech 文本 → 字幕条 → TTS 播放 + 波形 → 播完自动前进
🧩 交互层（覆盖） ← quiz / discussion 弹出 → 视觉保持、作答后收起

动作语义重定义

动作类型旧语义新语义
show_slide闪现一页 PPT视觉轨：切换/保持当前页（常驻；带 speech 字段则同时进语音轨）
launch_widget装载组件（3s 后消失）视觉轨：装载组件并常驻
widget_*重渲染组件并停留 5s驱动消息：发 postMessage 给常驻组件，视觉不变
wb_draw_*白板闪现 3s视觉轨：切换白板内容并常驻
speech独占内容区的大段文字语音轨：字幕条文本 + TTS，视觉保持当前
quiz / discussion独占界面交互覆盖层：视觉画布上弹出，答完收起
pause_for_thought空白等待视觉保持 + 「思考中」轻提示
scene_transition场景过渡动画场景级视觉切换动画

3前端改造详设

3.1 usePlayback：新增「视觉状态」管理

  • 新增 visualState（场景级 React state）：{ kind: 'slides'|'widget'|'summaryMap'|'whiteboard'|'none'; pageIndex?: number; payload?: any }
  • 场景进入时初始化默认视觉：
    • slide 场景 → kind:'slides' 默认显示第 1 页（pageIndex:0）
    • interactive 场景 → kind:'none'（空画布 + 「即将装载组件」占位）
    • review 场景 → kind:'summaryMap'（知识地图常驻）
    • quiz / discussion / 其他 → kind:'none'（显示场景标题装饰画布）
  • 执行动作时：
    • show_slide → 更新 visualState.pageIndex（或 summaryMap 标记）；若带 speech 文本 → 进语音轨；否则短暂停顿 600ms 后前进
    • launch_widget → visualState = {kind:'widget', payload}（常驻）
    • wb_draw_* → visualState = {kind:'whiteboard', payload}（常驻）
    • speech → 只进语音轨，不改视觉
    • quiz/discussion/pause_for_thought → 只改交互层，不改视觉
  • 场景切换时重置 visualState 为该场景默认视觉

3.4 兼容旧课堂（零迁移）

视觉常驻模型天然兼容旧动作序列：旧课堂的 show_slide 页面会在下一次视觉动作前持续显示，其间的 speech 变成字幕——比旧体验更好；无任何视觉动作的场景自动显示「场景标题 + 讲解字幕」兜底，无需数据迁移、无需重新生成。

4提示词模板对齐（后端）

更新 prompts/classroom/content-system.md 与两个子规则文件，让 LLM 产出符合「视觉常驻 + 语音字幕」的动作序列：

4.1 动作序列建议改写（content-system.md）

### 1. 讲授场景 (slide)

**核心范式：视觉常驻 + 语音配合（重要！）**
- 幻灯片是课堂的「视觉主引导」，**一经 show_slide 展示就常驻屏幕**，直到下一次换页
- 讲解词（speech）是「旁白字幕」，**不独占界面**，始终配合当前页讲解
- 节奏：一页幻灯片支撑 1~2 段讲解（每段讲 1 个知识点或 1 个要点）

动作序列建议：
show_slide(第1页·开场) → speech(讲开场要点) →
show_slide(第2页·图表) → speech(讲图表结论) → speech(深入分析) →
show_slide(第3页·归纳) → speech(小结) → pause_for_thought(思考) →
speech(收尾)

约束：
- 每个 slide 场景生成 2~4 页 slides（覆盖讲解全过程，不要只生成 1 页）
- speech 单段 ≤ 80 字（约 5~8 秒），方便学生读字幕；过长拆成多段
- show_slide 的 speech 字段只写「该页第一句引导语」（≤ 40 字），完整讲解用后续 speech 动作
- 严禁把完整讲稿写进 slides 元素（幻灯片只放关键词/图表/公式）

4.2 review / interactive 对齐

### 4. 回顾总结 (review)
show_slide(展示知识地图·常驻) → speech(逐分支回顾) → speech(第二分支) →
speech(金句收尾)
（知识地图展示后常驻，讲解字幕配合）

### 5. 动手探索 (interactive)
launch_widget(装载组件·常驻) → speech(说明操作) →
widget_set_state(演示状态) → widget_highlight(指向) →
speech(布置任务) → pause_for_thought(学生操作 8~15s) →
widget_annotate(总结规律) → speech(点评)
（组件装载后常驻整个场景，widget_* 只发驱动消息，不重新渲染）

验收标准

  1. 新课堂 slide 场景：PPT 页常驻 ≥ 2 页以上，讲解字幕逐句配合，PPT 不再"一闪而过"
  2. interactive 场景：组件装载后常驻整个场景，widget_* 驱动不重渲染、不闪烁
  3. quiz 场景：题目弹出时视觉保持（白板/页可见），作答后收起
  4. review 场景：知识地图常驻，讲解字幕配合
  5. 旧课堂：无需重新生成，播放体验自然升级（speech 变字幕、视觉常驻）
  6. 手动翻页不打断语音、全屏正常

不做的事（本期边界）

  • 不做视频轨/视频生成（未来视觉轨可扩展 video kind，本期不含）
  • 不做字幕逐字卡拉OK（做逐句高亮，精度与 TTS 同步成本高，二期可选）
  • 不重新生成存量课堂（兼容升级）
