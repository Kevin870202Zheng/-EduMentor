🎓 智慧课堂生成器（课堂生成中心）设计文档

版本 v1.1 · 2026-08-06 · 状态：已确认（6 项决策全部落档）
目标：将智慧课堂生成从「课程学习页」抽取为独立模块，支持两种生成场景

1. 背景与目标

现状：智慧课堂的生成入口只有学生课程学习页的「生成章级智慧课堂」按钮（仅 CHAPTER 节点可用，LEAF 被禁用）。生成管线强绑定单一知识点（classrooms.knowledge_point_id NOT NULL、大纲生成器输入为 KnowledgePoint），无法支持"任意多知识点聚合"与"非知识点素材"两类生成诉求。

目标：

  • 在智慧课堂模块内新建课堂生成器（生成中心），从课程学习页剥离生成能力。
  • 场景一：学生从课程知识点树勾选若干知识点或章节，直接生成针对这些知识点的智慧课堂。
  • 场景二：学段合作课堂——内置中华传统故事库，跨学段学生协作创作（小选故事 / 初中角色 / 高中台词 / 大学法律映射），发起者审阅修改后由大模型生成智慧课堂。

复用现有课堂播放器 / 场景大纲 / 场景内容生成管线 / LLM 服务 / 知识树 API / 学段档案体系。

3. 总体设计

课堂生成器 = 智慧课堂模块内的一个生成中心页面，提供两条生成流水线：

┌─────────────────────────────────────────────────────────────┐ │ 🎓 智慧课堂（学生端 / 教师端均可进入） │ │ ┌───────────────┐ ┌──────────────────────────────────┐ │ │ │ Tab1 我的课堂 │ │ Tab2 课堂生成器 │ │ │ │ · 已生成列表 │ │ ┌────────────────────────────┐ │ │ │ │ · 播放/进度 │ │ │ 场景一 知识点选择生成 │ │ │ │ └───────────────┘ │ │ 知识树勾选 → 聚合/批量生成 │ │ │ │ │ ├────────────────────────────┤ │ │ │ │ │ 场景二 学段合作课堂 │ │ │ │ │ │ 故事库 + 4学段分工协作 │ │ │ │ │ │ → 审阅 → AI 生成 │ │ │ │ │ └────────────────────────────┘ │ │ │ └──────────────────────────────────┘ │ └─────────────────────────────────────────────────────────────┘

两条流水线最终都汇入同一条课堂生成管线（场景大纲 → 逐场景内容 → 持久化），区别只在素材来源：

  • 场景一素材 = 勾选知识点的聚合文本（含章节展开的叶子知识点）
  • 场景二素材 = 故事原文 + 角色形象 + 台词 + 法律知识点内容

4. 场景一：知识点 / 章节选择生成

4.1 交互流程

选择课程→ 知识树勾选（章节=展开全选下级）→ 确认已选知识点（数量/时长预览）→ 选生成模式（聚合一课 / 每点一课）→ 命名 + 难度→ 生成（进度轮询）→ 进入课堂 / 回到列表

4.2 生成模式（关键决策）

模式行为适用实现
聚合模式（默认，推荐） 勾选的所有知识点聚合为一个课堂，LLM 将多个知识点编排进场景大纲 3~10 个知识点 / 章节（一章=若干知识点） 新增 ClassroomMaterial 聚合生成，knowledge_point_id 置空，metadata 记录 kpIds
批量模式 每个知识点各自生成一个课堂（沿用现有 generateFull 行为） 勾选数量大、或用户希望逐点成课 复用现有异步批量任务 + 轮询
📌 勾选超 10 个知识点时默认提示切批量模式，避免单课堂内容过载；章节勾选按「展开后全部叶子」计入数量。

4.3 后端改造

4.3.1 新增课堂素材抽象（生成管线解耦核心）：

class ClassroomMaterial {
    String title;                  // 课堂标题（用户命名或自动）
    String courseName;             // 课程名
    String knowledgeContext;       // 聚合内容文本（知识点 or 合作素材）
    List<UUID> knowledgePointIds;  // 关联知识点（聚合课堂记录多个）
    UUID courseId;                 // 所属课程
    int difficulty;                // 难度 1-5
}
  • SceneOutlineGenerator.generate(ClassroomMaterial, int difficulty) — 新增重载，复用现有 outline prompt 模板，将 knowledgeContext 填入聚合内容槽位
  • SceneContentGenerator — 无需改动（输入已是 outline + 文本上下文）
  • ClassroomGenerator.generateFromMaterial(material) — 新增编排方法，落库时 knowledge_point_id=null、source='MULTI_KNOWLEDGE'、metadata 存 kpIds + 生成模式

4.3.2 现有 generate 逻辑改造：generateClassroom(courseId, kpId, ...) 内部包装为单知识点 material，保持旧接口兼容。

4.4 API

POST /api/v2/classrooms/generate-from-selection
Body: { courseId, knowledgePointIds: [...], mode: "aggregated"|"batch",
        title?, difficulty, courseName }
聚合模式 → 同步返回课堂详情（一个课堂，生成耗时 ~30-60s 可接受）
批量模式 → 返回 { jobId }，沿用现有轮询

GET  /api/v2/classrooms/generate/{jobId}/status   （复用现有）

5. 场景二：学段合作课堂

5.1 角色分工（用户指定，固定映射）

学段角色任务内容产出物
🏫 小学 PRIMARY故事选择者从内置故事库选定故事story_id + 选择理由
📖 初中 JUNIOR角色形象设计师设计故事角色形象（姓名/性格/外观/背景）角色设定文本
🟢 高中 SENIOR台词编剧设计关键场景台词与对白台词脚本
🎓 大学 UNIVERSITY法律知识映射师从关联课程知识库选择法律知识点并说明映射关系知识点列表 + 映射说明

5.2 状态机

DRAFT 创建项目→ INVITING 邀请四学段学生→ COLLECTING 学生提交任务→ REVIEW 发起者查看/修改全部回复→ GENERATING AI 生成课堂→ PUBLISHED 课堂已发布
  • DRAFT：创建项目，填标题 / 关联课程 / 难度，可先浏览故事库
  • INVITING：每个角色从对应学段的学生列表中邀请 1 人（发起者手动选人）
  • COLLECTING：被邀学生收到待办 → 提交内容 → 任务 COMPLETED；全部 4 个任务完成才可进入下一步
  • REVIEW：发起者逐项查看、可修改任何任务内容 → 标记已复核
  • GENERATING：发起者点「确认生成」→ 聚合素材 → AI 生成课堂
  • PUBLISHED：生成完成，课堂出现在「我的课堂」，可播放

5.3 数据模型（V20 迁移）

-- 1. classrooms 放开知识点强绑定 + 生成来源
ALTER TABLE classrooms ALTER COLUMN knowledge_point_id DROP NOT NULL;
ALTER TABLE classrooms ADD COLUMN source VARCHAR(16) NOT NULL DEFAULT 'knowledge';
--   'knowledge' | 'multi_knowledge' | 'collaborative'

-- 2. 中华传统故事库（本期预置，后续公共化教师维护）
CREATE TABLE story_library (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    title       VARCHAR(255) NOT NULL,
    content     TEXT NOT NULL,               -- 故事原文
    dynasty     VARCHAR(64),                 -- 朝代/出处
    source_ref  VARCHAR(255),                -- 出处（如《世说新语》）
    keywords    TEXT,                        -- 关键词（逗号分隔）
    theme_id    UUID REFERENCES subject_themes(id),   -- 建议关联法律主题
    status      VARCHAR(16) DEFAULT 'published',
    created_by  UUID REFERENCES users(id),
    created_at  TIMESTAMPTZ DEFAULT now(),
    updated_at  TIMESTAMPTZ DEFAULT now()
);

-- 3. 协作课堂项目
CREATE TABLE collab_classroom_projects (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    title       VARCHAR(255) NOT NULL,
    description TEXT,
    course_id   UUID REFERENCES courses(id),     -- 法律知识来源课程
    creator_id  UUID NOT NULL REFERENCES users(id),
    story_id    UUID REFERENCES story_library(id),
    difficulty  INTEGER DEFAULT 3,
    status      VARCHAR(16) NOT NULL DEFAULT 'DRAFT',
    classroom_id UUID REFERENCES classrooms(id), -- 生成后的课堂
    metadata    JSONB,                           -- 聚合知识点等
    created_at  TIMESTAMPTZ DEFAULT now(),
    updated_at  TIMESTAMPTZ DEFAULT now()
);

-- 4. 协作任务（四角色）
CREATE TABLE collab_project_tasks (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    project_id      UUID NOT NULL REFERENCES collab_classroom_projects(id) ON DELETE CASCADE,
    role_type       VARCHAR(24) NOT NULL,  -- STORY_PICKER/CHARACTER_DESIGNER/SCRIPT_WRITER/LEGAL_MAPPER
    required_stage  VARCHAR(16) NOT NULL,  -- PRIMARY/JUNIOR/SENIOR/UNIVERSITY
    assigned_user_id UUID REFERENCES users(id),
    content         TEXT,                  -- 回复内容（JSON 文本，含 story_id/角色设定/台词/知识点映射）
    status          VARCHAR(16) DEFAULT 'PENDING', -- PENDING/COMPLETED/REVIEWED
    submitted_at    TIMESTAMPTZ,
    reviewed_at     TIMESTAMPTZ,
    created_at      TIMESTAMPTZ DEFAULT now(),
    updated_at      TIMESTAMPTZ DEFAULT now(),
    UNIQUE (project_id, role_type)
);

5.5 AI 生成素材聚合

生成时把四份产出物 + 故事原文聚合成 ClassroomMaterial：

素材标题：{故事名} · 法律智慧课堂（{课程名}）
素材内容 = 故事原文
         + 【角色形象】{初中产出}
         + 【台词脚本】{高中产出}
         + 【法律知识】{大学选中的知识点名称+内容+映射说明}
难度 = 项目难度

大纲 prompt 中注入"以故事为主线、法律知识为教学要点"的引导（复用现有 outline 模板 + 额外指引），生成课堂的 source='collaborative'、metadata 记录 project_id 与关联知识点。

8. 权限设计

  • 场景一：学生 / 教师均可发起生成（认证用户）
  • 场景二：仅教师可创建协作项目（creator 拥有审阅/修改/生成权限）；被邀学生仅能提交/修改自己的任务
  • 任务提交与复核均校验 project 状态机（非 COLLECTING 不可提交、非 REVIEW 不可复核）
  • 故事库：本期全员可读；后续公共库由教师创建 + 管理员审核
