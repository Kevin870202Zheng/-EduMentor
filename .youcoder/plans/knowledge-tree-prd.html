1. 背景与现状

现有问题

目前知识点在教师端和学生端均以扁平列表展示。例如教师端展示的知识点列表（「法的概念」「法的渊源」「法的制定」「刑法概述」「犯罪构成」等）全部平铺无序，缺乏学科内在的逻辑层级关系。

教师在解析上传资料时提取出的知识点是离散的，没有按照「编→章→节」的教材体系组织；学生在学习时看到的是零散的知识点列表，无法理解知识点之间的从属关系和逻辑递进。

核心痛点：知识点是孤立的，学生难以形成体系化的知识结构认知；教师缺乏一个高效的工具来将零散知识点组织成逻辑树。

现有基础

  • KnowledgePoint 实体已存在 parentKpId 字段（UUID，可为 null）— 天然支持父子层级
  • KnowledgeService 已存在 getKnowledgePointTree() 方法— 返回 KnowledgePointTreeNode(KnowledgePointDto, level, hasChild)
  • KnowledgeController 已有 GET /api/knowledge/courses/{courseId}/points/tree 端点
  • 知识点已有 orderIndex 排序字段
  • 教师端课程内容管理页面以 Ant Design Table 展示扁平知识点列表（TeacherCourseContent.jsx）
  • 学生端页面以左侧扁平列表展示所有知识点（StudentLearning.jsx）

2. 功能目标

🎯 核心目标

将课程知识点组织为「编→卷→章→节→知识点」的五层树状结构，让学生按照教材逻辑循序渐进地学习。

⚡ 交互目标

教师端提供「AI 生成树结构」按钮，一键基于课程所有知识点（包括已有和新知识点）自动生成/更新树结构。支持手动微调。

🔄 稳定性目标

重复生成时保留已有结构调整（如已有结构有效则不破坏），只对新增/删除/变化的知识点做增量调整，确保学生端学习进度不因为树重构而丢失。

📱 体验目标

学生端知识点导航从扁平列表改为可展开/折叠的树形导航，配合进度展示，清晰可见知识体系全貌。

3. 树状结构定义

层级模型

层级名称数据库中的角色说明
0课程（根）Course课程的根节点，不在知识点的 parentKpId 体系中
1编 (Volume)KnowledgePoint 但 type='VOLUME'课程的最大分区，如「民法总则编」「刑法总论编」
2卷 (Part)KnowledgePoint 但 type='PART'编下的细分（部分课程没有此层级）
3章 (Chapter)KnowledgePoint 但 type='CHAPTER'标准教材的章，如「第一章 法的概念」
4节 (Section)KnowledgePoint 但 type='SECTION'章下的节，如「第一节 法的定义」
5知识点 (Leaf)KnowledgePoint 但 type='LEAF'实际的学习单元（含练习题）
关键设计决策：「编」「卷」「章」「节」也是 KnowledgePoint 实体，只是 type 字段不同。它们也有 content（课程大纲描述）和 parentKpId，形成树状链。
理由：（1）不需要新建表或实体；（2）知识点关系（prerequisite）可以关联到章/节层面；（3）掌握度可以聚合计算；（4）前端树状渲染逻辑统一。

字段扩展

在 KnowledgePoint 实体中新增以下字段支持树结构：

字段名类型说明
typeString节点类型：VOLUME / PART / CHAPTER / SECTION / LEAF（已有知识点默认值为 LEAF）
sequencePathString路径编号，如 "1.2.3" 表示第一编第二章第三节（用于排序）
向后兼容：已有知识点的 type 自动设为 LEAF，sequencePath 设为 null，不影响现有功能。

树结构示例（法学概论）

📘 法学概论（课程） ├── 📖 第一编 法的基本原理 │ ├── 第一章 法的概念与本质 │ │ ├── 第一节 法的定义 │ │ │ ├── 📝 法的词源 │ │ │ ├── 📝 法的本质学说 │ │ │ └── 📝 法的特征 │ │ ├── 第二节 法的渊源与分类 │ │ │ ├── 📝 法的渊源 │ │ │ ├── 📝 法的分类 │ │ │ └── 📝 法的效力 │ │ └── 第三节 法的要素 │ │ ├── 📝 法律概念 │ │ └── 📝 法律规则 │ └── 第二章 法的运行 │ ├── 第一节 立法 │ │ └── 📝 立法程序 │ └── 第二节 司法 │ └── 📝 司法原则 └── 📖 第二编 宪法 └── 第一章 宪法基本理论 └── 📝 宪法的概念与特征

4. 教师端设计

4.1 页面改动

在「课程内容管理」页面中，在「新增知识点」按钮旁增加新按钮：

按钮位置触发
🔄 生成树结构顶部按钮栏右侧触发 AI 树结构生成弹窗

4.2 AI 生成树结构弹窗

  • 前置条件：课程必须已有至少 3 个知识点（否则提示"知识点太少，无法生成树结构"）
  • 弹窗内容：
    • 提示文案："AI 将根据当前课程的所有知识点，自动生成编→章→节的树状结构。已有结构将被参考保留，AI 会把新增知识点放入合适的层级位置。"
    • 显示当前知识点总量、已有树节点数（编/章/节的数量）
    • 生成粒度配置：下拉选择「按大学教材标准粒度（编→章→节）」或「按小节粒度（仅章→节）」
    • 「确定生成」按钮 + loading 状态

4.3 知识点列表改为树形展示

知识点列表从扁平 Table 改为可展开的 Tree 组件展示：

  • 使用 Ant Design Tree 组件（或 Table 配合 tree-data 模式）
  • 每个节点显示图标（📖 编/📕 章/📄 节/📝 知识点）
  • 点击知识点显示其习题列表（保留原有展开功能）
  • 支持拖拽调整顺序（需要在 Tree 上启用 draggable）
  • 工具栏在选中的知识点上操作（编辑、删除、AI 出题、新增习题）
交互细节：教师可以手动拖拽调整树结构。手动调整后再点「生成树结构」，AI 会以当前手动调整后的结构为基础做增量生成，而不会彻底推倒重来。

4.4 差异对比模式

当课程已有树结构，再次点击「生成树结构」时，弹窗增加：

  • 📊 上次生成后的变化概览：
  • ✅ 已有树节点：10 个（编×2，章×5，节×3）
  • 🆕 新增知识点：3 个
  • 🗑️ 已删除知识点：1 个（仅标记不删除）
  • 🔄 变化知识点：2 个（内容有更新）
  • 渲染方式：在树中的新增/变化/删除节点旁添加差异标签（🆕 新增 / 🔄 变更 / 🗑️ 待删除）

5. 学生端设计

5.1 知识点导航改为树形目录

学生端学习页面的左侧知识点列表从扁平列表改为可折叠展开的树形导航：

  • 默认展开到「章」层级（全部展开也可以，看数据量）
  • 每个节点左侧显示掌握度小圆点颜色（未学习/学习中/已掌握）
  • 点击「节」或「知识点」节点 → 加载该节点下的所有子知识点题目的合集（聚合模式）或跳转到第一个知识点

5.2 学习内容布局

当用户在树中选择一个节点时：

  • 点击「编」或「章」→ 显示该层级下所有子知识点的内容概览页面（聚合摘要）
  • 点击「节」→ 加载该节下的所有知识点为连续学习内容（按 orderIndex 排序）
  • 点击「知识点（LEAF）」→ 保持现有行为：显示知识点内容 + 练习题

5.3 进度可视化的树

  • 编/章/节节点显示聚合掌握度进度条（基于子节点的掌握度平均值）
  • 节点图标颜色区分：🟢 已掌握（≥80%） / 🔵 学习中（50-79%） / 🟡 待巩固（20-49%） / ⚪ 未学习（＜20%）
  • 顶部展示整体学习进度百分比

5.4 学情诊断的树状联动

  • 智能答疑辅导：在提问时系统可感知当前学习的树节点上下文
  • 学习路径建议：基于树结构生成「推荐学习路径」（先学编1→章1→节1，再编1→章1→节2，推荐学习路径...
  • 错题复盘：按树结构分类展示薄弱点（错误集中在「法理学·法的运行·司法」章节）

6. AI 树结构生成算法

6.1 算法流程

收集知识点 → 加载已有树 → 比对 diff → Prompt 构建 → LLM 生成 → 解析合并 → 保存入库

6.2 输入参数

调用 LLM 时，将以下信息组装为 Prompt：

数据维度内容作用
📌 课程信息课程名称、描述、学科让 AI 理解学科背景
📝 全部知识点所有知识点的 name + description + content 摘要（每条 100 字以内）让 AI 了解有什么内容需要组织
🏗️ 现有树结构已有的编/卷/章/节节点名称和层级关系（序列化 JSON）稳定性关键：告知 AI 已有结构
🔍 差异数据 - 新增知识点列表（上次生成之后新出现的）
- 已删除知识点列表（曾存在但现已不在）
- 内容变更的知识点列表 		让 AI 做增量调整

6.3 Prompt 模板（核心）

系统指令：
你是一个课程知识结构专家。请根据提供的课程知识点列表，生成或更新该课程的树状知识结构。

要求：
1. 按照「编 → 章 → 节 → 知识点」四层结构组织，使用最合适的层级深度
2. 优先保留已有的树结构：对于已有的编/卷/章/节节点，尽量保留其名称和层级关系
3. 将新增知识点放入最合适的已有章节中，必要时创建新的章节
4. 已删除的知识点对应的章节节点保留（如果还有其他有效知识点）
5. 内容变更的知识点保持在原位置不变
6. 每个节点用 type 标记：VOLUME / PART / CHAPTER / SECTION / LEAF
7. 返回纯 JSON 数组，不要包含其他内容

输出格式：
[{"name":"编的名称","type":"VOLUME","order":1,"children":[
  {"name":"章的名称","type":"CHAPTER","order":1,"children":[
    {"name":"节的名称","type":"SECTION","order":1,"children":[
      {"kpId":"知识点ID","name":"知识点名称","type":"LEAF","order":1},
      ...
    ]},
    ...
  ]},
  ...
]},...]

6.4 稳定性保障策略

策略说明
保留旧节点 ID已有树节点（VOLUME/CHAPTER/SECTION）保存后有 UUID，再次生成时传给 Prompt，AI 在返回中引用这些 UUID，程序解析时保留原有 ID
模糊匹配如果 AI 返回的新节点 name 与旧节点 name 相似度 > 0.8（如「法的概念与本质」vs「法的概念」），自动匹配为同一节点
知识点位置不动已有 LEAF 节点（知识点）在已有树中已有位置，除非知识点的 name/content 变化超过 50%，否则保留原位置
后端校验解析 LLM 返回后，做交叉校验：所有 LEAF 的 kpId 必须在课程知识点范围内；任何遗漏的知识点自动追加到「其他」节

6.5 手动调整支持

  • 教师可以拖拽树节点调整层级
  • 教师可以手动创建/删除节点（在编辑知识点弹窗中 parentKpId 改为树选择器）
  • 再次 AI 生成时，手动调整被视为「已有树结构」的一部分被保留

7. API 设计

7.1 新增 API

方法路径说明权限
POST/api/knowledge/courses/{courseId}/points/tree/generateAI 生成/更新课程知识点树结构TEACHER / ADMIN
PUT/api/knowledge/points/{id}/move移动知识点到新父节点TEACHER / ADMIN

7.2 请求/响应定义

POST /api/knowledge/courses/{courseId}/points/tree/generate

请求体字段类型说明
granularityString生成粒度：STANDARD（编→章→节）或 COMPACT（仅章→节）

响应体：

字段类型说明
treeTreeNode[]完整的嵌套树结构
statsObject统计：总节点数、新增节点数、保留节点数、删除节点数
orphanedKpIdsUUID[]未找到归属的知识点 ID 列表（如果有）

PUT /api/knowledge/points/{id}/move

请求体字段类型说明
parentKpIdUUID新的父节点 ID（null 表示移到根层级）
orderIndexInteger在新父节点下的排序位置

7.3 现有 API 增强

方法路径增强内容
GET/api/knowledge/courses/{courseId}/points/tree返回的 tree 中每个节点包含 type 字段和差异标记
GET/api/knowledge/courses/{courseId}/points可选参数 type 过滤节点类型
POST/api/knowledge/pointsKnowledgePointCreateRequest 增加 type 和 parentKpId 字段
PUT/api/knowledge/points/{id}KnowledgePointUpdateRequest 增加 type 字段

8. 数据模型变更

变更说明
knowledge_points.type新增字段，VARCHAR(16)，默认 'LEAF'，可选值：VOLUME/PART/CHAPTER/SECTION/LEAF
knowledge_points.sequence_path新增字段，VARCHAR(32)，可为 null，如 "1.2.3"
索引新增 idx_kp_type 索引
无新建表：所有树节点都存储在 knowledge_points 表中，通过 type 区分。已有数据的 type 自动设为 LEAF。LEAF 节点保留其 content（学习内容）。VOLUME/CHAPTER/SECTION 节点的 content 可以存该层级的教学大纲概述。

⚠️ 风险和注意事项：
  1. LLM 生成质量不确定：需要准备多个学科的测试课程（法学、数学、计算机等）验证 Prompt 效果。如果效果不理想，需要迭代 Prompt
  2. 已有数据迁移：已有知识点的 type 全部设为 LEAF，不会出现不兼容
  3. 掌握度聚合：学生端树的聚合掌握度基于子知识点掌握度的加权平均值，当前学情诊断 API 需要确认是否支持子节点聚合查询
  4. 拖拽排序：Ant Design Tree 的 draggable 需要手动处理 onDrop 事件，更新 parentKpId 和 orderIndex
  5. 移动端适配：树形导航在窄屏幕上可能需要折叠为抽屉菜单
