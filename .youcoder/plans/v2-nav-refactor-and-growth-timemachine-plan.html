📦 EduMentor v2.0 版本规划

信息架构重构 · 缺陷修复 · 成长时光机（新功能）

版本：v2.0 状态：待评审 预估工时：约 7.5 人天 来源：6 项用户验收反馈

🎯0. 版本目标

针对上一轮用户体验验收提出的 6 项反馈，本版本完成：

  • P0 缺陷：修复「课堂生成时知识树无法加载」的 404 根因。
  • P1 信息架构重构：学习路径入口迁移、智慧课堂拆分并入课程学习、智慧课堂更名合作课堂、模拟法庭入口隐藏。
  • P2 新功能：落地 PRD「场景 F 成长时光机」——跨学段自我对话与成长记录。
⚠️ 重要说明：经代码核查，反馈中提到的「时光机功能」在现有代码库与 plans 目录中没有独立实现，仅在 .youcoder/plans/multi-stage-legal-education-prd.html 的「场景 F：成长时光机 — 跨学段自我对话与成长记录」中有产品场景描述。 本版本将以该场景为蓝本从零落地（此前朋友版本可能实现过，但本项目库未包含）。

🐛4. P0 缺陷修复：知识树加载失败

4.1 根因（已确认）

环节内容结论
后端端点 GET /api/knowledge/courses/{courseId}/points/tree（KnowledgeController L212） 存在
前端调用（KnowledgePointPicker） knowledgeApi.getKnowledgePointTree(courseId) → 请求 GET /api/knowledge/points/tree?courseId=xxx 404
对照：课程学习页可用 knowledgePointAPI.getTree(courseId) → 请求 GET /api/knowledge/courses/{courseId}/points/tree（services/api.jsx L345） 正常
返回结构 后端返回扁平列表 [{knowledgePoint, level, hasChild}]，前端 toTreeData 期望嵌套 children 结构不兼容

4.2 修复方案

  1. 修正 URL：knowledgeApi.ts 的 getKnowledgePointTree 改为路径参数 /knowledge/courses/${courseId}/points/tree（与 services/api.jsx 对齐，消除双封装差异）。
  2. 修正树构建：KnowledgePointPicker.jsx 的 toTreeData 改为支持扁平列表 （含 knowledgePoint.parentKpId / hasChild），复用 StudentLearning.jsx L565-663 的 childrenMap + 递归 buildChildren 逻辑（或抽取为公共工具函数）。
  3. 统一封装：建议将「课程知识树」收敛到单一 API 来源，避免 api/knowledgeApi.ts 与 services/api.jsx 两套并存（下版本可合并，本版仅修 URL）。
  4. 回归验证：学生端 + 教师端各跑一次「知识树勾选 → 聚合生成课堂」全链路。
影响面：此缺陷同时影响学生端与教师端的场景一（知识树勾选生成），修复后可解锁「课程学习中心 Tab3 课堂生成」。

⏳5. P2 新功能：成长时光机

5.1 需求来源（PRD 场景 F 原文）

「小红刚升入初中，系统自动弹出她在小学阶段的学习报告——法律与规则掌握度 92%，宪法精神 78%，但公民权利仅 65%。 系统建议她优先复习再学新课。接着，她打开了一封"来自过去"的信：小学三年级的自己曾问"法律为什么能管住所有人？" 她笑着打字回答。系统将这一切收录进她的"法治素养成长档案"，生成了一张从小学到初中的认知深度跃迁曲线图。」

5.2 功能拆解

⏳ 认知深度跃迁曲线

跨学段、跨时间维度的主题掌握度 / 认知深度变化折线图（echarts）。

📂 法治素养成长档案

按学段归档的学习记录：各主题掌握度、答题统计、完成课堂数、薄弱点演变。

✉️ 来自过去的信

学生创建"寄给未来/来自过去"的信件：AI 基于历史薄弱点生成提问，学生回答，存档。

🎓 学段晋升报告

检测学段身份变更时，自动生成「上一学段学习报告 + 下一学段学习建议」。

5.3 数据模型（V23 迁移）

-- 成长时光机：信件表
CREATE TABLE time_machine_letters (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    student_id  UUID NOT NULL REFERENCES users(id),
    stage       VARCHAR(20) NOT NULL,              -- 写信人所在学段（过去的自己）
    course_id   UUID REFERENCES courses(id),
    direction   VARCHAR(10) NOT NULL DEFAULT 'PAST_TO_NOW', -- 过去→现在 / 现在→未来
    question    TEXT NOT NULL,                     -- 来自过去的提问（AI 生成或手写）
    answer      TEXT,                              -- 现在的回答
    ai_generated BOOLEAN DEFAULT TRUE,
    answered_at TIMESTAMP,
    created_at  TIMESTAMP DEFAULT now(),
    updated_at  TIMESTAMP DEFAULT now()
);

-- 成长档案快照（晋升/学期末自动归档）
CREATE TABLE growth_archive_snapshots (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    student_id  UUID NOT NULL REFERENCES users(id),
    stage       VARCHAR(20) NOT NULL,              -- 归档时所在学段
    course_id   UUID,
    summary     JSONB NOT NULL,                    -- {themeMastery:{}, totalQuestions, accuracy, weakKps:[], depthStats:{}}
    created_at  TIMESTAMP DEFAULT now()
);

5.4 后端 API

方法端点说明
GET/api/time-machine/overview?studentId=总览：跃迁曲线数据 + 各学段档案摘要
GET/api/time-machine/archives?studentId=成长档案列表（按学段）
GET/api/time-machine/letters?studentId=信件列表（含已答/待答）
POST/api/time-machine/letters创建信件（可携带学段；question 留空则 AI 生成）

POST/api/time-machine/archive手动归档快照（晋升时自动调用）

  • 曲线数据来源：聚合 diagnosis（知识掌握）、student_profiles.stage（学段）、 growth_archive_snapshots（归档快照），无需额外埋点。
  • AI 提问生成：复用 LLMService，prompt 基于该学段历史薄弱知识点 + 该学段典型认知问题生成提问。
  • 晋升检测：修改 StudentProfileService.updateStage，学段变化时自动生成归档快照 + 晋升报告草稿。

5.6 边界与空状态

  • 跨学段数据缺失：当前学生均只有大学学段数据。第一期真实数据仅显示现有学段曲线； 提供 scripts/seed-time-machine.sql 造一套小学→初中→高中→大学的演示档案，便于验收。
