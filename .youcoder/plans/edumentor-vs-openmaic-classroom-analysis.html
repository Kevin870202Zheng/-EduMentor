EduMentor vs OpenMAIC 电子课堂功能对比分析

分析目的：找出 EduMentor 课程展示前端效果远不如 OpenMAIC 的根本原因，产出可执行的改进方向。

结论先行：EduMentor 的"沉浸课堂"并非不完整，而是在视觉体验、交互深度、内容渲染、动画反馈、生成预览、AI 角色塑造六大维度上全面落后。OpenMAIC 经历了更长的迭代周期，其 Stage 组件体系是一个经过深度打磨的、可编辑的、多媒体丰富的课件播放引擎，而 EduMentor 的 ClassroomPlayback 更接近一个最小可行性原型（MVP）。

二、课程展示核心架构差距

2.1 渲染模型对比

维度EduMentorOpenMAIC
核心组件ClassroomPlayback.tsx（296 行）Stage.tsx + PlaybackChromeRoot.tsx（~2000 行）
场景类型线性 Action 列表（speech/quiz/whiteboard/discussion）4 种独立场景：slide（画布）、quiz（问卷）、interactive（交互 iframe）、pbl（项目式学习）
内容渲染纯文本 + 基本卡片 + 简单 Radio 选择题画布式 Slide 渲染器：支持文本/图片/形状/表格/代码/LateX/视频/图表等 10+ 元素类型

2.2 Slide/课件渲染 — 最大差距所在

这是 EduMentor 与 OpenMAIC 之间最根本的差距。

OpenMAIC 的 Slide 渲染器是一个完整的画布式课件引擎，文件结构如下：

  • Canvas 层：components/slide-renderer/Editor/Canvas/ — 无限画布、网格线、缩放
  • 元素层：10 种元素类型（Text / Image / Shape / Table / Code / LaTeX / Video / Chart / Line / Group）
  • 每个元素都有独立的 Base*Element + 编辑态 + 播放态
  • 支持：锚点对齐、旋转、阴影、描边、渐变填充、透明度、裁剪路径
  • 支持：Spotlight 高亮叠加层（SpotlightOverlay.tsx）
  • 缩放/平移、全屏演示模式、画布比例自适应

EduMentor 的"白板"只是一个简单的 WhiteboardRenderer.tsx（55 行）：

  • 一个带虚线边框的 Card 组件
  • 纯文本内容展示（action.text || action.wbContent）
  • 无图形、无图片、无表格、无公式、无代码高亮
  • 更致命的是：白板内容仅作为纯文本从 AI 生成，不是结构化的画布元素

2.3 场景导航对比

EduMentor：横向排列的 Ant Design Button 列表（classroom.scenes.map），只显示标题文本。

OpenMAIC：可拖拽宽度的侧边栏（220px~400px），每个场景以可视化缩略图展示：

  • Slide 场景：实时缩略图 SlideThumbnail，展示画布上的所有元素
  • Quiz 场景：模拟 2×2 选项网格小图
  • Interactive 场景：浏览器窗口 + iframe 实时预览
  • PBL 场景：看板式三列 Kanban 小图
  • 生成中的场景：skeleton pulsing 动画 + 失败状态（错误图标 + 重试按钮）
  • 课程完成标记：金色 Trophy 图标 + 星形装饰

3.2 大纲/生成预览 — EduMentor 完全缺失

OpenMAIC 的 generation-preview/page.tsx（1581 行）是一个完整的课程生成预览系统：

  • 6 个步骤可视化：PDF 解析 → 网络搜索 → 大纲流式生成 → AI 智能体自动创建 → 课件内容生成 → 教学动作生成
  • 每个步骤都有独立的 StepVisualizer 动画组件（visualizers.tsx，848 行）
  • 大纲流式展示：SSE 实时推送 + 时间线圆点动画
  • 可交互的大纲编辑（用户可在大纲生成后修改/确认）
  • Agent Reveal Modal：Flip Card 翻牌动画展示 AI 讲师
  • Web Search 结果集成展示

EduMentor：课堂是异步生成的（POST /api/v2/classrooms/generate），用户在列表页看到"生成中"状态等待，无任何生成过程的视觉反馈。

四、AI 角色与交互深度差距

4.1 虚拟讲师/智能体

OpenMAIC：

  • 完整的 Agent 系统：自动生成 AI 讲师角色（名称/角色/人设/头像/语音）
  • 12 种预设头像（教师/助教/好奇者/记录员/思考者等），Flip Card 翻牌动画展示
  • Discussion Trigger：AI 同学在讲课时主动提问打断
  • Roundtable 圆桌讨论组件：多人 AI 对话
  • Agent 语音分配 + TTS 配置
  • Chat Area 聊天区：课程讲解 + 即时问答 + SSE 流式输出

EduMentor：

  • DiscussionRenderer.tsx 中仅显示一个硬编码的 "AI同学 小E"
  • 无头像、无角色定制、无语音
  • 课件讲解仅是静态文字展示，无 TTS 播放
  • 无问答交互功能

4.2 TTS（文字转语音）

OpenMAIC：完整的 TTS 系统，支持：

  • 多种 TTS Provider（browser-native / OpenAI TTS / 其他服务商）
  • 生成时预先生成 TTS 音频并存储
  • 播放时 audioPlayer 控制音量/语速/静音
  • 讨论时实时 TTS

EduMentor：无 TTS 功能。

六、总结：EduMentor 的根本问题

核心结论：EduMentor 的"沉浸课堂"是一个功能性 MVP，而非沉浸式体验。

根本差距不在于某个单一的"bug"或"缺失功能"，而是以下 6 个维度的全面落后：

P0 — 最严重问题（必须优先解决）

P0 课件的视觉呈现 OpenMAIC 的核心是画布式 Slide 渲染器（10+ 元素类型），而 EduMentor 仅用纯文本展示。课件是课堂的"界面"，如果课件本身不好看，整个课堂就不好看。
P0 缺少生成预览 OpenMAIC 的 6 步生成预览 + 流式大纲 + 动画反馈是用户"被惊艳到"的第一印象。EduMentor 让用户面对一个"加载中"的 Spin。
P0 缺乏动画与微交互 EduMentor 没有任何动画框架，页面是"静态"的。OpenMAIC 使用 motion 在每个环节都注入了弹性动画、渐变、扫描线、辉光等。

P1 — 重要问题

P1 无 TTS / 语音讲解 课堂应该是"听得见的"，但 EduMentor 的"讲解"只是静态文本。
P1 AI 角色单一且无视觉表现 OpenMAIC 有 12 种 AI 讲师头像 + 角色卡翻牌动画。EduMentor 只有文本 "AI同学 小E"。
P1 场景导航缺少缩略图 EduMentor 的场景导航是文本按钮列表；OpenMAIC 的侧边栏有实时视觉缩略图。

P2 — 改进项

P2 缺乏全屏/演示模式 OpenMAIC 支持全屏演示 + 自动隐藏控件。
P2 无国际化（i18n） OpenMAIC 完整支持多语言。
P2 播放引擎过于简单 EduMentor 使用 useRef + setTimeout；OpenMAIC 使用独立 PlaybackEngine 类 + 状态机。

七、改进建议路线图

Phase 1 (MVP 升级) — 快速见效

  • 引入动画库：安装 motion (Framer Motion)，为场景切换、Action 过渡、加载状态添加基础动画
  • 改进场景导航侧边栏：从横向 Button 改为左侧 SceneSidebar，增加场景类型图标和基本的视觉缩略图
  • 替换白板渲染器：将 WhiteboardRenderer 从纯文本升级为支持 Markdown / KaTeX 数学公式 / 代码高亮的渲染器
  • 添加生成进度反馈：在课堂生成过程中显示步骤进度条（哪怕只有 3 步：大纲→内容→完成）
  • 增加 AI 讲师头像：至少为不同角色（教师/助教）显示不同的圆形头像和颜色

Phase 2 (体验提升) — 核心重构

  • 重构播放引擎：从 usePlayback hook 升级为独立的状态机类，支持断点续播、Action 重放
  • 添加 TTS 功能：集成浏览器原生 TTS 或云端 TTS API，让 speech 动作实际发声
  • 建设生成预览页：仿照 OpenMAIC 的 generation-preview，在课堂生成时展示流式大纲和进度
  • Ant Design 逐步替换：引入 Tailwind CSS + Radix UI 原语，逐步替换重型 Ant Design 组件
  • Slide 渲染器初步建设：先从 Text + Image + 表格 3 种元素开始，构建基础的画布式 Slide 组件

Phase 3 (追赶 OpenMAIC) — 长期目标

  • 完整的画布式 Slide 渲染器（10+ 元素类型）
  • AI Agent 系统：自动生成讲师角色、个性化头像、语音分配
  • 讨论/问答交互：Chat Area + SSE 流式对话
  • 全屏演示模式
  • PBL 场景支持

八、决定性差距总结

最后用一个简单的方式总结：

OpenMAIC 的电子课堂是一个「AI 驱动的沉浸式课件播放器 + 实时交互平台」。

EduMentor 的电子课堂是一个「结构化的课件内容序列展示器」。

EduMentor 的功能骨架（Action 序列、场景划分、Quiz 提交）是合理的，但缺乏以下三个让体验"飞起来"的关键要素：

  1. 动画：没有 motion 级别的动画库支持，所有过渡都是生硬的切换
  2. 视听沉浸感：没有 TTS、没有 AI 角色视觉化、没有课件本身的丰富视觉渲染
  3. 生成过程的仪式感：没有用动画和步骤分解来让用户感知"AI 正在为你创建课程"的过程

如果不解决 P0 的三项问题（课件渲染、生成预览、动画体系），EduMentor 的"沉浸课堂"将始终停留在"能用但不好看"的阶段。
